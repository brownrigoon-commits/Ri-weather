# 00. 개요 — 배경·확정 요구사항·로드맵

## 목적

이지어드민 WMS에 있는 재고·주문·배송 데이터를 Claude가 대화로 조회하게 하는
**로컬 전용, 읽기 전용 MCP 서버** (1단계). 최종 목표는 슬랙에서
"A브랜드 이번주 재고 얼마 남았어?" 같은 질문에 Claude가 답하는 것(2단계)이다.

## 확정 요구사항 (사장님 인터뷰 결과 — 변경 시 사장님 승인 필요)

| 항목 | 확정 내용 |
|---|---|
| 데이터 원천 | 이지어드민 WMS 단일. 모든 조회·확인은 이지어드민 기준 |
| 접근 방식 | **엑셀 + API 이중 지원.** API가 안 되면 엑셀로, API가 되더라도 실무자가 엑셀을 선호할 수 있음. 어느 쪽으로든 동작해야 함 |
| API 보유 여부 | **미확인.** 이지어드민 API는 신청제(법인, 건당 과금, 세팅 약 3일). 문의: apidev@pimz.co.kr / https://www.ezadmin.co.kr/api/index.html |
| 기능 범위 | 아래 4개 + 진단 1개. **추가 금지** |
| 우선 업무 | 주문·배송·반품/교환 조회가 최다 사용. 재고는 부차 |
| 브랜드 구분 | 두 방식 병행: ① 상품명·상품코드에 브랜드 식별자 포함 ② 브랜드별 판매처(몰)·이지어드민 계정 분리 |
| 개인정보 | **기본 마스킹**(홍길동→홍*동). 추후 업무상 원본이 필요할 수 있어 설정으로 전환 가능하되 기본값은 항상 마스킹 |
| 사용 환경 | Windows PC, Python `C:\Python314`. Claude Desktop과 Claude Code **둘 다** 연결 |
| 제약 | 쓰기·수정·삭제 기능 절대 금지. 접속 정보는 `.env` 분리. README에 실행·테스트 방법. 프로젝트 규칙은 CLAUDE.md |

## 기능 (확정)

1. **재고조회** `inventory_lookup` — SKU나 브랜드명으로 현재 수량 및 재고 위치
2. **주문조회** `order_lookup` — 기간이나 주문번호로 내역
3. **미출고목록** `unshipped_list` — 접수됐지만 출고 안 된 건
4. **배송조회** `shipping_lookup` — 출고·반품 배송이 어떤 상황인지, 택배사 송장 조회로 확인
   (1단계는 택배사별 조회 링크 제공. 실시간 배송추적 API 연동은 비목표)
5. **상태진단** `data_status` — 연결 확인·데이터 신선도·설정 요약 (Claude Desktop 연결 테스트에 사용)

## 로드맵

| 단계 | 내용 | 상태 |
|---|---|---|
| P1 | 로컬 읽기 전용 MCP 서버. 엑셀 소스로 완전 동작, API 소스는 스켈레톤 | **이번 구현 범위** |
| P1.5 | 이지어드민 API 명세 수령 후 `config.json`의 api 섹션 채워 API 소스 활성화 | 명세 수령 대기 |
| P2 | 슬랙 연동 (원격 MCP 또는 슬랙 봇). PII는 masked/summary 강제 | 설계만 별도 진행 예정 |

## 비목표 (1단계에서 하지 않는 것)

- 쓰기 작업 일체 (주문 상태 변경, 재고 조정, 송장 등록 등)
- 이지어드민 화면 자동 다운로드(셀레늄 등) — 실무자가 받은 엑셀 파일을 폴더에 두는 것으로 충분
- 택배사 실시간 추적 API 연동 — 조회 링크 생성으로 대체
- 슬랙 연동, 원격 배포, 다중 사용자 인증

## 남은 확인 사항 (구현과 병행 가능)

1. **API 인증키 보유 여부** — 이지어드민 계약 담당자에게 확인. 결과와 무관하게 P1은 진행 가능
2. **실제 엑셀 샘플 확보** — 구현은 샘플 데이터로 진행하되, 완료 판정 전 실제 이지어드민
   엑셀 1벌(주문·재고·반품)로 헤더 매핑·상태 정규화를 반드시 검증할 것 (02 문서 참고)
