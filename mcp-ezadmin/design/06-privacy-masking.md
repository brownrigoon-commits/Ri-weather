# 06. 개인정보 보호 — 마스킹

주문·배송 데이터에는 고객 이름·전화번호·주소가 들어 있다. 최종 단계(슬랙)에서는 답변이
채널에 남으므로, **기본값은 항상 마스킹**이고 원본 표시는 의식적으로 켜야만 가능하다.

## pii_mode (`.env`의 `EZMCP_PII_MODE`, 기본 `masked`)

| 모드 | 동작 |
|---|---|
| `masked` (기본) | PII 필드를 아래 규칙으로 마스킹해 표시 |
| `summary` | PII 필드(수취인·주문자·전화·주소·extras의 PII 의심 컬럼)를 응답에서 **아예 제거** |
| `full` | 원본 그대로. 로컬 전용·업무상 필요할 때만. 서버 시작 시 stderr에 경고 로그, `data_status`와 모든 응답 meta에 `"pii_mode": "full"`이 표시되게 해 인지 상태를 유지 |

- 코드 기본값을 `full`로 바꾸는 변경은 금지 (CLAUDE.md 절대 규칙)
- P2(슬랙)에서는 masked 또는 summary를 강제하고 full을 설정으로도 막는다 (P2 설계에서 확정)

## 마스킹 규칙 (`masking.py`)

| 대상 | 규칙 | 예 |
|---|---|---|
| 이름 (수취인·주문자) | 1자→`*` · 2자→첫자+`*` · 3자 이상→첫자+`*`×(길이−2)+끝자 | 홍길동→`홍*동`, 남궁민수→`남**수` |
| 전화번호 | 숫자만 추출해 마지막 4자리 앞 4자리를 `*`로. 하이픈 포맷 유지 | 010-1234-5678→`010-****-5678` |
| 주소 | 공백 기준 앞 3토큰 유지 + ` ***` (시/구/동 수준까지만) | 서울 강남구 역삼동 123-4 5층→`서울 강남구 역삼동 ***` |
| 이메일 | 로컬파트 앞 2자+`***`+`@도메인` | brown.rigoon@gmail.com→`br***@gmail.com` |
| 주문번호·송장번호 | **마스킹하지 않음** (업무 식별에 필수) | |

## extras(미매핑 컬럼)의 PII 필터

상세 조회에서만 노출되는 extras는 원본 헤더 기준으로 처리한다:

- 헤더가 전화/휴대폰/핸드폰/연락처/주소/우편번호/이메일/메일/메모/배송메시지/요청사항 또는
  이름 계열(수취인/수령인/수하인/주문자/구매자/받는사람/받는분)이면 —
  `masked`: 값에 이름·전화 규칙 적용이 불가능하므로 **값 전체를 `(마스킹됨)`으로 대체**,
  `summary`: 제거, `full`: 원본
- 그 외 extras는 모든 모드에서 원본 (상품·물류 정보로 간주)

## 로그·오류 정책

- 로그(stderr)에 고객 이름·전화·주소·인증키를 절대 남기지 않는다.
  파일명·행수·상태값 같은 메타 정보만 로깅
- 오류 메시지에도 레코드 원문을 포함하지 않는다 (주문번호까지는 허용)

## 저장소 위생

- 실데이터(`data/`)와 실설정(`.env`, `config.json`)은 gitignore — 이미 설정됨
- 샘플 데이터 생성기는 **실존 인물이 아닌 가상 이름·전화·주소만** 생성한다
