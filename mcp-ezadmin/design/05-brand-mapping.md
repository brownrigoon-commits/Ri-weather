# 05. 브랜드 매핑

확정 사실: 이지어드민 안에서 브랜드는 **두 방식이 병행**된다.
① 상품명·상품코드에 브랜드 식별자가 들어 있음 ② 브랜드별 판매처(몰)·이지어드민 계정 분리.
따라서 매칭도 두 기준을 모두 사용한다.

## 설정 스키마 (`config.json`의 `brands`)

```jsonc
"brands": {
  "루미네": {                            // 표시 이름 (질문에 쓰는 이름)
    "aliases": ["lumine", "루미네코리아"],  // 사장님이 쓸 수 있는 다른 호칭
    "product_keywords": ["LM-", "[루미네]"], // 상품명·상품코드 부분 일치 키워드
    "malls": ["루미네 자사몰", "스마트스토어-루미네"], // 판매처(mall) 컬럼 값
    "accounts": ["lumine"]                 // API accounts[].name 또는 계정 구분값
  },
  "베르디": {
    "aliases": ["verdi"],
    "product_keywords": ["VD-"],
    "malls": ["베르디 자사몰"],
    "accounts": []
  }
}
```

## 매칭 규칙

1. 입력 브랜드명 해석: `brands`의 키 또는 `aliases`에서 찾는다.
   비교는 정규화(소문자화·공백 제거) 후 정확 일치
2. 레코드가 브랜드에 속하는 조건 — 아래 중 **하나라도** 참이면 매칭 (OR):
   - `brand_col` 값이 브랜드 키 또는 aliases와 일치 (정규화 후)
   - `mall` 값이 `malls` 목록의 항목과 일치 (정규화 후 정확 일치)
   - `product_name` 또는 `product_code`에 `product_keywords` 중 하나가 **원문 그대로
     부분 포함** (키워드는 정규화하지 않는다 — `LM-` 같은 접두어의 대소문자·기호가 의미 있음)
   - 레코드에 붙은 계정명이 `accounts`에 있음 (API 소스, 03 문서)
3. 등록되지 않은 브랜드로 질문하면: 오류가 아니라
   `{"안내": "등록되지 않은 브랜드입니다. 등록된 브랜드: 루미네, 베르디. config.json의 brands에 추가할 수 있습니다."}`
   를 반환해 Claude가 바로 안내하게 한다
4. `brand` 파라미터가 빈 값이면 브랜드 필터 없음(전체)

## 운영 규칙

- 브랜드 목록·키워드는 **비밀은 아니지만 사업 정보**이므로 실제 값은 `config.json`
  (gitignore 대상)에만 두고, 저장소의 `config.example.json`에는 가상 브랜드
  (루미네/베르디) 예시만 둔다
- 신규 브랜드 온보딩 = config에 항목 추가가 전부여야 한다 (코드 수정 없이)
- `data_status`의 `브랜드` 항목으로 현재 등록 목록을 확인할 수 있다
