# 해외 진출 조사 — 일본·중국 (2026-07-31)

일본 측과 앱 논의를 앞두고, **지금 앱이 붙어 있는 한국 플랫폼들을 일본·중국에서 무엇으로
갈아끼울 수 있는지**와 **두 나라 구장 데이터로 코스공략이 가능한지**를 조사한 기록이다.
전부 실제로 검색·문서 확인·샘플 페이지 파싱까지 한 결과이고, **확인 못 한 것은 못 했다고 적었다.**

## 한 줄 결론

- **일본은 간다.** 한국보다 조건이 오히려 좋다 — 부킹·조인·숙박이 **라쿠텐 공식 API 하나**로
  덮이고(제휴 수익까지 합법), 홀별 공략 데이터도 **공식 사이트에 SVG 홀맵째로** 공개돼 있다.
- **중국은 파트너 없이는 불가.** 기술이 아니라 **제도**가 막는다. 지도·위치 서비스는 외자
  단독 불가(합작 필수), 구글이 차단돼 **캐디(Gemini)·음성(Google TTS)·배포(GitHub Pages)
  세 축이 전부 죽는다.** 구장도 409곳뿐이고 정책적으로 줄고 있다.

### 일본 — 핵심은 라쿠텐 계정 하나로 세 기능이 덮인다

- **라쿠텐 GORA API 3종** (`webservice.rakuten.co.jp`)
  - 골프장 검색 / **골프장 상세** / **플랜 검색**
  - 플랜 검색이 **빈자리 재고 상태·재고 수·플레이일·요금(총액/세부)·2B3B 추가금·취소료**까지 준다.
    한국 골팡은 이걸 절대 안 준다 — **"우리 예보로 날짜 고르면 그 날 빈자리까지 보여준다"가
    일본에선 화면 안에서 완결된다.**
  - **제휴 ID를 파라미터에 넣으면 제휴 URL을 API가 만들어 준다** → 수익화가 약관 안에서 합법.
  - 제휴 코스 약 2,000곳 = 일본 전체(2,110~2,154곳)의 대부분.
  - App ID·Access Key 필요, 무료로 보이나 **상업 이용 조건은 문서에 명시가 없어 미확인** — 계약 전 확인 필요.
  - 제한: 동일 URL 단시간 대량 호출 시 HTTP 429.
  - ⚠️ **홀별 데이터는 없다** (코스 전체 거리·홀수·파·그린종류·고저차까지만). 좌표와 이미지 5장은 있음.
- **라쿠텐 트래블 API** — 키워드검색/시설정보/시설검색이 현행(버전 2026-07-31), 제휴 URL 생성 가능.
  ⚠️ **레거시 API는 2026-02-09 폐지됨** — 옛 예제 코드를 그대로 쓰면 안 된다.
- **핫페퍼 그루메 API(리크루트)** — 무료로 보이나 조건이 있다:
  **크레딧 표기 의무**(이미지 또는 텍스트), **음식점에서 대가를 받는 사업 금지**,
  **점포 정보 자체의 재판매 금지**. 제휴 수익은 허용. 타베로그는 공개 API가 없다.
- **날씨** — JMA가 `www.jma.go.jp/bosai/forecast/data/forecast/{지역코드}.json` 으로 예보를 낸다.
  정부표준 이용약관 적용이나 **정식 WebAPI로 공표한 것은 아니다**(대량 접근·재배포는 확인 필요).
  지금 쓰는 Open-Meteo가 전 세계를 덮으므로 **날씨는 사실상 그대로 가도 된다**(상업용은 유료 플랜).
- **음성** — Chirp3-HD가 `ja-JP` 지원. 화자 8종(Kore/Aoede 등) 그대로. **Code.gs 의 voices 배열 한 줄**이면 일본어 캐디가 나온다. 월 100만 자 무료는 언어와 무관.

### 중국 — 막는 것은 기술이 아니라 제도

1. **지도·위치 서비스**: 「외국 조직·개인의 중국 내 측량 관리 잠정 방법」상 **외자는 내비게이션
   전자지도 편제 불가**, 인터넷 지도 서비스는 **합작·합자 형태로만** 허가된다.
   → 가오더/바이두 키 발급 자체가 **중국 법인 실명 인증**을 요구한다.
2. **좌표계**: 중국 내 지도는 GCJ-02(화성좌표). 우리 DB의 WGS-84 좌표를 그대로 찍으면 **수백 m 어긋난다.**
3. **구글 전면 차단**: 캐디(Gemini)·음성(Google TTS)·**배포처(GitHub Pages)** 가 모두 구글/깃허브다.
   GitHub 은 중국에서 접속이 불안정하고 2025-04 에는 미로그인 중국 IP 403 사고도 있었다.
   → **앱을 통째로 다른 스택에 올려야 한다**(국내 호스팅 + ICP 비안 + 국산 LLM/TTS).
4. **부킹 플랫폼**: 云高高尔夫(300여 구장)·铁马高尔夫·爱玩高尔夫·城市高尔夫·星际高球联盟.
   云高의 `apidoc.bookingtee.com` 을 열어봤으나 **실제 API 문서가 아니라 서비스 안내였다** —
   공개 API 여부 확인 못 함. 제휴는 전화(4001850006) 등 직접 접촉이 필요하다.
5. **시장 크기**: 골프장 **409곳(2023)**, 2014년 이후 정책적 규제로 **감소 추세**. 일본의 1/5.

## 3. 코스공략 가능 여부 — 이게 핵심 질문이었다

우리 코스공략은 **홀별 파 + 티별 거리 + 홀맵 그림**이 있어야 성립한다(없으면 "준비중" 배너).
7/29 에 확정한 원칙 그대로다 — **파·거리가 추정치면 캐디를 내보내지 않는다.**

### 🇯🇵 일본 — **가능. 한국보다 조건이 좋다.**

**실제로 확인했다.** PGM(파시픽골프매니지먼트) 공식 사이트는 전 구장이 같은 템플릿이다:

```
https://www.pacificgolf.co.jp/{구장코드}/course_plain.asp
```

PGM남이치하라GC 1번홀을 열어 실측한 값:

| 항목 | 값 |
|---|---|
| 파 | 4 |
| 티별 거리 | 블루 380Y · 화이트 347Y · 레드 288Y |
| HDCP | 9 |
| 홀맵 | `img_layout/A-h01.svg` — **SVG(벡터)** |
| 공략문 | "전체적으로 약간 오르막인 미들홀. 첫 타는 정면 느티나무 방향이 노림수…" |

18홀 전부 같은 형식. **한국에서 만든 `universal_build.py` 계열 파서가 그대로 붙는다.**

- **PGM 약 150곳 + 아코디아 172곳 = 321곳**이 같은 그룹(平和)이고 사이트 템플릿이 표준화돼 있다.
  일본 전체의 약 15%를 **파서 두 개**로 덮는다. 한국에서 구장마다 파서를 새로 짰던 것에 비하면 훨씬 싸다.
- **SVG라서 한국 래스터 이미지보다 유리하다** — 홀맵 세로 600 표준화가 리샘플링 손실 없이 된다.
- 공략 코멘트가 **구장 공식 문장**이라, 지금 앱의 "공식 TIP" 자리에 그대로 들어간다.
- 나머지 1,800여 곳은 한국과 같은 방식(구장별 공식 사이트 수집)으로 점진 확장.
- 좌표·기본정보·예약은 **GORA API가 2,000곳을 합법적으로** 준다 → 홀 데이터가 없는 구장도
  "부킹은 되고 코스공략만 준비중" 상태로 정상 서비스된다. **한국의 231/2,000 구조와 동일.**

⚠️ **저작권은 반드시 협의 테이블에 올려야 한다.** 홀맵 SVG·공략문은 구장/PGM 저작물이다.
한국에서 골프존 자료에 대해 만들어 둔 **`golfzon_takedown.py`(통지 오면 일괄 내리기)** 와
같은 안전장치를 일본판도 처음부터 넣거나, **이번 일본 논의에서 정식 이용 허락을 받는 편이 낫다.**
지금 논의 중인 상대가 유통·플랫폼 쪽이라면 **이 항목이 협상 카드가 된다.**

### 🇨🇳 중국 — **현 시점 사실상 불가.**

- 표본으로 관란호(觀瀾湖, 216홀 12코스) 등을 확인했으나 공개된 것은 **코스 총 야드·대표홀 소개**
  수준이고, **홀별 티별 거리표나 홀맵을 공식 사이트에서 제공하는 구장을 찾지 못했다.**
- 구장 자체가 409곳이라 수집 대상이 적고, 회원제·비공개 성향이 강해 데이터 공개 유인이 없다.
- 설령 홀 데이터를 모아도 **지도 표시·좌표·AI·음성·호스팅이 전부 제도에 막힌다**(2절 참고).
- 결론: **중국은 "데이터 문제"가 아니라 "법인·파트너 문제"다.** 중국 파트너(합작 법인)가
  생기기 전에는 개발을 시작할 이유가 없다.

## 4. 앱 다국어(ja/zh) 작업 규모 — 참고

- 지금 문구는 `index.html` + `js/*.js` 에 **한국어 하드코딩**이다(app.js만 5,569줄).
  언어팩 분리 → `t("key")` 치환이 선행 작업이다. 한 번 해두면 두 번째 언어는 싸진다.
- **AI 캐디는 프롬프트 언어만 바꾸면 된다** — Gemini가 일본어를 만든다. 다만 한국어 말투 개편
  (7/30 v166~167: 구어체·호칭·색깔 금지)을 **일본어로 다시 다듬어야 한다.** 그대로 번역하면
  일본 골퍼에게 어색한 존대·호칭이 나온다. 실측 없이 내보내면 안 되는 영역.
- 약관·개인정보 처리방침은 **일본 APPI 기준으로 다시 써야 한다**(좌표 미수집 원칙은 그대로 유리하게 작용).

## 5. 권고 순서

1. **일본 먼저, 중국은 파트너가 생기면.** 두 나라를 동시에 벌리면 둘 다 못 한다.
2. 일본 논의 자리에서 확인할 것 — **① GORA API 상업 이용 조건(문서에 명시 없음)**,
   **② PGM/아코디아 홀맵·공략문 이용 허락**, ③ 제휴 수익 배분.
3. 기술 착수 순서: 언어팩 분리 → GORA API 연동(부킹/조인) → PGM·아코디아 321곳 홀 수집 →
   일본어 캐디 말투 다듬기 → 라쿠텐 트래블·핫페퍼.
4. **좌표는 계속 수집하지 않는다.** 한국에서 정한 원칙(위치기반서비스 신고 회피)이
   일본 APPI·중국 PIPL 에서도 그대로 유리하다.

## 6. 이 조사에서 확인하지 못한 것 (다음 사람 몫)

- GORA API 의 **상업 이용 가부·과금 여부** — 문서에 명시가 없다. 라쿠텐에 직접 문의해야 한다.
- **GDO·자란골프의 API 공개 여부** — 공개 문서를 찾지 못했다(제휴 문의 필요).
- 핫페퍼 API 의 **호출 상한·앱에서의 이용 가부** — 이용안내 페이지에 기재가 없다.
- 云高高尔夫 등 중국 플랫폼의 **API 존재 여부** — 문서 사이트가 실제 API 문서가 아니었다.
- 아코디아 공식 사이트의 **홀별 데이터 유무** — 코스가이드 URL 이 404 였다. PGM 은 확인됨.
  (아코디아도 있을 가능성이 높지만 **확인 전까지는 PGM 150곳만 확실한 것으로 친다.**)
