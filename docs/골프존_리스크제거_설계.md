# 골프존 리스크 제거 스위치 설계 (2026-07-29, 클라우드 세션)

사장님 지시: **"리스크 제거 버튼을 만들어 주세요."**
구현 순서: **① 캐디 개편(`docs/코스공략_캐디_설계.md`) → ② 이 문서.** 구현은 로컬 오퍼스5.

## 0. 이 스위치가 무엇인가

골프존에서 수집한 자산(홀맵 이미지·영상 프레임·3D영상 링크·티별 거리 데이터, **212개 구장**)을
**한 번의 실행으로 배포본에서 전부 내리는** 운영 도구.

- 권리자 통지가 오면 **1시간 내(실제 소요 ~10분) 합법 상태로 복귀**하기 위한 것.
- "몰랐다"가 아니라 **"리스크를 알고 감수하되, 통지 즉시 내린다"는 리스크 관리 방침**의 실행 수단.
- 내려도 앱은 깨지지 않는다 — 해당 구장은 **자동으로 위성 뷰 + "캐디 공략 준비중" 화면으로 강등**
  (캐디 개편 v2.1의 ②모드가 바로 이 안전망. 개편 전이라도 기존 위성 분기가 있어 동작은 함).
- 제휴가 성사되면 **복구도 한 번의 실행**으로.

## 1. 실측 근거 — 지워야 할 것의 전체 목록 (2026-07-29 확인)

| 대상 | 위치 | 규모 | 확인 방법 |
|---|---|---|---|
| 수집 원데이터 | `coursedata/homepages/gz*/` | 212개 폴더 | `parsed.json`의 `"source": "골프존 코스 데이터"` 212건 전부 gz* 폴더에만 존재 |
| 홀맵 이미지·영상 프레임 | `holeimg/gz*/` | 212개 폴더 (구장당 ~68파일) | 홈페이지 출처 구장(19곳) parsed.json에는 golfzon 문자열 **0건** — 오염 없음 |
| 3D영상 핫링크 | `js/holeimgdb.js` 안 3,834개 | 조립 산출물 | `build_holeimgdb.py`가 `homepages/*/parsed.json`을 훑어 조립 → **gz 폴더 삭제 후 재조립하면 자동 소멸** |
| 약관 출처 표기 | `js/legal.js` `<li>골프존 — 홀 정보</li>` | 1줄 | 실측 |
| HOLES_DB | `js/holesdb.js` | **이미 비어 있음** (신뢰 원칙으로 과거 전량 제거) | 실측 |
| 부수물 | `coursedata/registrable_analysis.json` 등의 골프존 공식 홀수 수치 | 사실 정보 수준 | 낮은 우선순위 — `--status`가 목록만 보고 |

핵심: **골프존 자산과 홈페이지 자산이 폴더 단위로 완전히 분리**되어 있어(gz 접두사),
"gz* 삭제 → 재조립"이 곧 완전한 제거다. 새 검증으로 이를 이중 확인한다(4장).

## 2. 도구 설계 — `tools/golfzon_takedown.py`

```
python tools/golfzon_takedown.py --status    현황: 골프존 자산 목록·규모 출력 (변경 없음)
python tools/golfzon_takedown.py --check     검증: 작업본에 골프존 흔적 0인지 검사 (변경 없음)
python tools/golfzon_takedown.py --remove    제거: 아래 절차 실행 (확인 문구 입력 요구)
python tools/golfzon_takedown.py --restore   복구: 태그에서 자산 원복 + 재조립
```

### `--remove` 절차 (순서 고정)

1. **복구 태그 먼저**: `git tag golfzon-assets-<APP_VER>-<날짜>` — 지우기 전에 되돌아갈 지점 박기.
2. `git rm -r coursedata/homepages/gz* holeimg/gz*`
3. `python tools/build_holeimgdb.py` 재조립 → 남은 ~19개 구장만으로 `js/holeimgdb.js` 생성.
4. `js/legal.js`에서 `<li>골프존 — 홀 정보</li>` 줄 제거 (문자열 완전 일치로만 — 다르면 중단하고 보고).
5. 자체 `--check` 실행: `js/` `index.html` 산출물에 `golfzon`·`gz` 경로 참조 **0건**,
   `holeimgdb.js` 구장 수 = 남은 parsed.json 수, 중괄호 균형 (release와 같은 무결성 기준).
6. 사람에게 다음 단계 안내 출력 (도구가 직접 push하지 않는다 — 배포는 항상 표준 관문 경유):
   ```
   python tools/release_courses.py "코스 자료 정리"
   python tools/verify_deploy.py --wait
   ```
   `release_courses.py`가 버전을 올리므로 기존 사용자 폰의 캐시(sw.js)도 다음 실행 때 갱신된다.

### `--restore` 절차

1. `git checkout <태그> -- coursedata/homepages holeimg` (gz 경로 원복)
2. `legal.js` 줄 되살리기 → 재조립 → `--check` 역방향(구장 수 복귀) → 표준 배포 안내.

### 안전장치 (전부 필수)

- `--remove`는 **`내리기`라는 확인 문구를 직접 입력**해야 실행 (212개 구장이 내려가는 파괴적 작업).
- 시작 전 `git status` 깨끗함 확인 — 다른 작업과 섞인 채 실행 금지.
- 시작 전 `tools/sync.py` 받기 실행 — 상대 PC 작업을 받은 최신 위에서 지운다 (동시 작업 충돌 방지).
- 태그 생성 실패 시 즉시 중단 (복구 지점 없이 지우지 않는다).

### 사장님용 버튼 — `tools/골프존_내리기.bat`

`ristock_실행.bat`과 같은 패턴: 더블클릭 → 경고문 표시 → `내리기` 입력 →
`--remove` → `release_courses.py` → `verify_deploy.py --wait` 까지 한 번에.
마지막 줄에 "내려간 구장 수·앱 버전·verify 통과 여부"를 출력하고 창을 유지한다.
(통지받은 날 사장님이 개발자 없이도 혼자 내릴 수 있어야 진짜 버튼이다.)

## 3. 내려간 뒤 앱의 모습

- 골프존 유래 212구장: 코스공략 진입 시 `HOLEIMG_DB`에 없으므로 기존 분기(`js/app.js` 1866행~)를
  타고 **위성 뷰 + "캐디 공략을 준비중입니다"** 표시 (캐디 개편 v2.1 ②모드).
- 홈페이지 허락 기반 19구장: 홀맵·샷별 캐디 정상 동작.
- 검색·날씨·맛집·숙박·스코어: 영향 없음 (`golfdb.js` 위치 정보는 사실 데이터로 별개).

## 4. 검증 계획 (배포 전 필수 — 실배포 없이 리허설)

1. **리허설**: 로컬에서 `--remove` 실행(푸시 없이) → `holeimgdb.js`에 19구장·golfzon 문자열 0건 확인
   → 로컬 서버에서 gz 구장 하나 열어 위성+준비중 화면 확인(elementFromPoint 실터치)
   → `git reset --hard` + 태그 삭제로 원상 복귀. **이것이 이 도구의 "일부러 고장 내서 확인"이다.**
2. `--check`를 일부러 속여서 검증: gz 파일 하나를 남긴 채 돌려 검사가 잡는지 확인 후 원복.
3. `--restore` 리허설: 리허설 1에서 복구까지 돌려 원상 복귀를 확인 (제거만 검증하고 복구를
   안 검증하면, 제휴 성사 날 복구가 안 되는 사고가 난다).
4. `tools/sweep.js` 또는 별도 검사에 추가: holeimgdb.js 안 golfzon 링크 수와 gz 폴더 수의
   일치(현황 감시) — 내리기 전에는 존재 확인, 내린 뒤에는 0 확인에 재사용.

## 5. 한계 — 사장님이 알고 계셔야 하는 것

- **git 이력에는 과거 파일이 남는다.** 서빙(GitHub Pages)은 즉시 중단되며 실무상 그것이 핵심.
  이력까지 완전 삭제(history rewrite)는 집·회사 동시 작업 저장소를 전부 다시 맞춰야 하는
  큰 작업이라 **별도 결정 사항** — 권리자가 명시적으로 요구할 때만 검토.
- 이 스위치는 책임을 없애 주지 않는다. 과거 사용분의 책임은 남되, 즉시 중단으로
  손해 누적이 멈추고 분쟁이 실무적으로 종결되는 효과를 노리는 것.
- 사용자 폰에 캐시된 옛 이미지: 버전업으로 다음 실행 때 갱신 — 즉시 원격 삭제는 불가(PWA 특성).
