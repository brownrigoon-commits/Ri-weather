# 코스공략 AI 캐디 개편 설계 v2 — "샷별 캐디" (2026-07-29, 클라우드 세션)

사장님 지시 (2026-07-29, 두 차례):
1. 지금 공략은 **홀 전체를 한 덩어리로** 설명해서 길고 오래 걸린다. 나이 드신 분들이
   티박스에서 다 읽고 스윙하기 무리. 군더더기 빼고 **자신감을 심어주는 캐디**로.
2. **파 기준으로 샷별 분리**: 티샷(드라이버) 공략 / 세컨샷 공략 / 서드샷(그린 주변 어프로치) 공략.
   그린 플레이는 그린 정보가 거의 없으니 **생략하되, 그린 정보가 있으면 감안**해서
   상황에 맞는 공략을 각각 넣는다.
3. 각 공략을 **밝고 자신감을 불어넣는 여성 음성**으로 들을 수 있게.
4. 속도: 홀 이동하며 듣는 것이라 빨라야 하지만, **속도 때문에 퀄리티를 떨어뜨리는 건 최악**.
5. (3차 지시) **홀별 파악이 어려운 구장은 "캐디 공략을 준비중입니다" + 위성사진**으로.

구현은 로컬 오퍼스5가 진행. 이 문서는 그 작업 지시서다.

## 2. 설계 A — 출력: 파 기준 "샷별 캐디"

### 파별 구성 (한 번의 호출로 전부 생성)

| 파 | 항목 | 비고 |
|---|---|---|
| 파3 | **티샷 → 그린 주변** | 파3의 세컨샷은 곧 그린 주변 대처(어프로치·벙커) |
| 파4 | **티샷 → 세컨샷** | 세컨샷 = 온 시도. 그린 주변 대처는 세컨샷 항목 안에 한 줄로 |
| 파5 | **티샷 → 세컨샷 → 서드샷** | 세컨샷 = 레이업/2온 판단, 서드샷 = 어프로치 |
| +그린 | `h.green` 있을 때만 **그린** 항목 추가 | 경사도 이미지를 첨부해 "핀 어느 쪽이 안전한지" 수준만. **없으면 항목 자체를 만들지 않는다** (원칙 2: 틀릴 수 있으면 표시하지 않음 — 현재 18홀만 보유) |

### 항목별 길이 규칙

- **티샷: 1~2문장, 90자 이내** — 호칭 + 구질 맞춤 조준점 + 클럽 + 자신감. 가장 공들일 항목.
- **나머지: 1~2문장, 70자 이내** — 지시 하나 + 위험 하나.
- 호칭("싱글 골퍼님" 등)은 **티샷에서만** 부른다. 항목마다 반복하면 음성이 늘어진다.
- 격려("좋은 결과가 있을 겁니다!")는 **마지막 항목 끝에 한 번만**.
- 파5 전체 합계 ~280자 — 지금의 4~6문장 산문보다 짧으면서, 샷마다 끊어 들을 수 있다.

### 응답 형식 — 줄 단위 라벨 (JSON 아님)

```
[티샷] 싱글 골퍼님, 미스가 적으시니 좌측 카트도로를 보고 드라이버로 과감하게 스윙하세요. 페이드가 중앙으로 돌아옵니다.
[세컨샷] 남은 거리보다 한 클럽 길게 잡고 그린 앞 벙커 너머 중앙만 보세요.
[서드샷] 56도로 핀보다 그린 가운데를 노리는 게 버디 퍼트를 남기는 길입니다. 좋은 결과가 있을 겁니다!
```

- JSON을 쓰지 않는 이유: 파싱 실패 시 전량 유실 위험 + 나중에 스트리밍(6장 2단계)을 붙일 때
  줄 단위가 그대로 이어진다.
- 클라이언트 파싱: `/^\[(티샷|세컨샷|서드샷|그린 주변|그린)\]/` 줄 분리.
  **라벨이 하나도 안 잡히면 통짜 텍스트 그대로 한 카드에 표시** (내용을 잃지 않는 폴백).
- 프롬프트에 파별 라벨 목록을 **정확히 지정**하고 "이 라벨 외 다른 줄 금지"를 못 박는다.

### 프롬프트 수정 지침

- 형식 문단 교체: "①②③ 순서로 4~6문장" → 위 라벨 형식 + 항목별 글자 수 + "목록·이모지 금지,
  음성으로 읽기 좋은 문장". 형식 지시는 **프롬프트 맨 끝**에 (마지막 지시의 이행률이 높다).
- 캐릭터 한 줄 교체: "친절한 한국인 캐디" → "밝고 자신감 넘치는 투어 경력의 여성 캐디.
  플레이어에게 확신을 주는 말투" (음성 페르소나와 일치).
- 파를 코드가 알고 있으므로 **파에 맞는 라벨 목록을 코드에서 만들어** 프롬프트에 넣는다
  (모델에게 "파를 보고 알아서 나누라"고 하지 않는다 — 항목 누락/추가 변동을 없앤다).
- `h.green` 있는 홀: 경사도 이미지를 첨부하고 라벨에 `[그린]` 추가 +
  "그린 경사도 이미지(빨강=높음, 파랑=낮음)를 근거로만 말하라" 지시.
- `playerTraitGuide()`의 "~한 줄 곁들이세요"류는 "**문장 수를 늘리지 말고 해당 샷 지시에
  녹이세요**"로 다듬는다 (예: 90대의 "힘 빼고 부드럽게"는 티샷 문장 안에).
- 지어내기 금지 원칙 그대로. 그린 정보 없는 홀에서 그린 얘기 금지를 명시.
- **검증 안전판**: 파싱된 라벨 수가 기대와 다르거나 전체 400자 초과면 형식 지시를 강조해
  **1회만** 재시도. 그래도 실패면 받은 그대로 표시 (자르거나 지어내지 않는다).

### 톤 예시 (프롬프트에 few-shot 1세트 포함)

- 싱글·페이드 티샷: "싱글 골퍼님, 미스가 적으시니 좌측 카트도로를 보고 드라이버로 과감하게 스윙하세요. 페이드가 페어웨이 중앙으로 돌아옵니다."
- 90대·슬라이스 티샷: "90대 골퍼님, 왼쪽 러프 끝을 보고 힘 빼고 부드럽게만 치세요. 오른쪽 벙커만 피하면 됩니다."
- 입문자 티샷: "골퍼님, 페어웨이 한가운데만 보고 우드로 편하게 치세요. 왼쪽 연못은 쳐다보지 않으셔도 됩니다."

## 2-1. 제공 범위 — 샷별 캐디는 등록 구장만, 나머지는 "준비중" + 위성사진

코스공략 화면은 지금 세 단계로 갈린다 (`js/app.js` 1866~1948행):

| 단계 | 구장 | 지금 동작 | 개편 후 |
|---|---|---|---|
| ① 등록 구장 | `HOLEIMG_DB` 보유 (232구장·4,239홀) | 공식 홀맵 + AI 캐디 | **샷별 캐디 제공** (이 문서의 본론) |
| ② OSM 홀 라인만 있는 구장 | Overpass `golf=hole` 데이터 | 위성 홀 뷰 + **위성사진만 보고 AI 캐디** (2466~2490행) | AI 캐디 제거 → **"캐디 공략을 준비중입니다" + 위성사진(기존 위성 홀 뷰 유지)** |
| ③ 자료 없는 구장 | — | "홀별 공략을 준비 중" 배너 + 위성 전경 (1928~1948행, 이미 구현) | 그대로 (문구만 ②와 통일) |

### ②에서 AI 캐디를 빼는 근거 (사장님 지시 + 기술적 근거 일치)

- ②의 **par는 공식 자료가 아니라 홀 길이로 추정**한 값이다 (1975행: `len < 230 ? 3 : ...`).
  샷별 캐디는 **par로 항목 수를 정하는 구조**라, par 추정이 틀리면 세컨샷/서드샷 구성
  자체가 틀린다. 자신감을 주는 여성 음성으로 **확신에 차서 틀리는 것**이 최악의 조합.
- 벙커·해저드도 OSM 공개 데이터라 누락이 많다. 원칙 2(틀릴 수 있으면 표시하지 않음) 그대로.

### ② 화면 구성

- 위성 홀 뷰(`renderHoleCanvas` 세로 위성사진)와 지도 홀 라인은 **그대로 유지** — 이게 "위성사진".
- AI 캐디 버튼 자리에 문구: `🛠 이 구장의 캐디 공략을 준비중입니다` (③ 배너와 같은 스타일,
  앱 이름 하드코딩 없음). 버튼은 숨긴다 — 눌리는데 안 되는 버튼을 남기지 않는다.
- 기존 로컬 규칙 공략(`buildHoleStrategy` — 구질·꺾임 방향 안내)은 AI가 아니고 화면에
  근거(위성 라인)와 함께 보이므로 유지. 단 사장님이 함께 빼길 원하시면 같은 자리에서 제거
  (결정 항목 ④).

### 정리 효과

- 위성사진 AI 캐디 분기(2466~2490행)와 `holeSatelliteDataUrl`의 AI 전송 경로가 삭제돼
  코드가 단순해지고, 프롬프트는 홀맵 모드 하나만 관리하면 된다.
- Gemini 무료 한도도 신뢰할 수 있는 구장에만 쓰게 된다.

## 3. 설계 B — 화면: 샷별 카드 + 각각 음성

`#ai-strategy` 통짜 `<p>` → 샷별 카드 목록으로 교체 (course-view, index.html 380행대 + css).

```
⛳ 티샷      [멘트 큰 글씨]   🔊
🏌️ 세컨샷    [멘트]          🔊
🎯 서드샷    [멘트]          🔊
🟢 그린      [멘트]          🔊   ← h.green 있는 홀만
                     [▶ 전체 듣기]
```

- **글자 크게** (기존 `.ai-strategy`보다 1~2단계) — 나이 드신 분 가독성이 이 개편의 출발점.
- 카드마다 🔊 (그 샷만 재생, 재생 중엔 ⏹). **응답 도착 시 티샷만 자동 재생** —
  버튼을 누른 순간 골퍼는 티박스에 있다. 세컨샷부터는 이동하며 해당 카드를 탭.
- `▶ 전체 듣기`: 전 항목을 순서대로 연속 재생 (utterance를 순서대로 speak하면
  speechSynthesis가 알아서 큐로 이어 읽는다).
- 버튼 문구: `🤖 AI 캐디 상세 공략 보기` → `🎧 AI 캐디 공략 듣기` (문구는 사장님 확인 ③).

## 4. 설계 C — 음성: 기기 내장 TTS (Web Speech API)

### 왜 내장 TTS인가

| | 기기 내장 (speechSynthesis) | 클라우드 TTS |
|---|---|---|
| 비용 | **0원** | 과금 + 키 관리 |
| 지연 | **0초** (기기 안에서 합성) | 오디오 생성+다운로드 1~2초 추가 |
| 오프라인 | 대부분 동작 | 불가 |
| 품질 | 기기별 편차 (아이폰 유나는 준수) | 균일하게 높음 |

홀 이동 중 즉시 들려야 하고 사용량 절약 원칙이 있으므로 **1단계는 내장 TTS**.
클라우드 TTS는 품질 요구가 커지면 2단계 별도 과제.

### 여성 음성 선택 (`pickKoVoice()`)

```js
// 우선순위: 알려진 여성 한국어 음성 → 아무 ko 음성 → null(음성 UI 조용히 숨김)
const PREFER = ["Yuna", "유나",              // iOS·맥 기본 한국어 (여성)
                "Google 한국의",              // 안드로이드 크롬
                "Microsoft Heami", "Heami"];  // 윈도우
```

- `getVoices()`는 첫 호출에 빈 배열일 수 있다 → `voiceschanged`에서 재선택.
- 밝은 톤: `pitch = 1.1`, `rate = 1.0~1.05` (실기기로 들어보고 확정).
- ko 음성이 없으면 🔊·전체 듣기를 숨기고 텍스트만. 오류문 없음
  (어색한 영어 억양으로 읽느니 침묵 — 원칙 2의 음성판).

### 재생 흐름과 iOS 함정 (실기기 검증 필수)

1. **iOS 제스처 잠금 해제**: 캐디 버튼 탭 핸들러 **안에서 동기적으로** 빈 utterance를
   한 번 `speak()` 해 오디오를 깨운 뒤, 응답 도착 후 진짜 멘트를 speak.
2. **끄기 토글**: 설정에 "음성 캐디" on/off (`localStorage`, 기본 켬). 끄면 1번도 생략.
3. **cancel 배선**: 새 홀 선택(`renderImgCourse`의 `sel()`)·화면 이동·새 요청·다른 카드 🔊 탭 시
   `speechSynthesis.cancel()`. 안 하면 이전 멘트가 겹치거나 이어 나온다.
4. iOS 무음 스위치가 켜져 있으면 안 들릴 수 있다 — 감지 불가. 🔊 버튼이 있으니 추측성 안내문은 넣지 않는다.
5. 크롬 "긴 발화 15초 멈춤" 버그: 항목당 70~90자라 해당 없음. **전체 듣기도 항목별
   utterance를 나눠 큐잉**하므로 안전 (하나로 합쳐 읽지 말 것).

### 읽기 전처리 (`speechText()`)

- 라벨(`[티샷]`)·이모지·괄호 제거, `350m` → `350미터`, `파3` → `파 3`.
- 화면과 음성은 **같은 문장** (전처리만 다름). 따로 생성하지 않는다.

### 코드 배치

`js/app.js` AI 캐디 구역에 함수 4개(`pickKoVoice` `speechText` `speakCaddie` `parseCaddie`)로 충분.
새 파일을 만들면 index.html `<script>` 줄 추가가 필요한데 **index.html은 로컬이 부킹 작업 중**
— 수정을 `#ai-strategy` 카드 주변(380행대)으로 최소화하고, 고치기 전 부킹 구역과 겹치지 않는지 확인.

| ✗ | 모델을 flash-lite로 내림 | — | **하지 않는다** (퀄리티 우선). lite는 지금처럼 폴백만 |

- 버튼의 `(3~8초)` 표기는 개선 후 실측값으로 갱신.
- 예상 2~4초. 예상일 뿐 — 문서·화면에는 실측만 적는다. 부족하면 ⑥.

## 5-1. 속도 실측 (2026-07-29 구현 중, 실제 Gemini API로 측정)

예상이 여러 곳에서 빗나갔습니다. **여기 적힌 것만 사실입니다.**

### 무엇이 느린가 — 생각(thinking) 토큰이 전부였습니다

`gemini-flash-latest` 는 지금 **`gemini-3.6-flash`** 로 연결됩니다(응답의 `modelVersion` 실측).
이 모델은 캐디 멘트 한 줄을 만들 때도 **생각 토큰을 1,300~2,100개** 씁니다(출력은 80~90개).

| 조건 | 응답 시간(3회) | 생각 토큰 |
|---|---|---|
| 개편 전 (4~6문장 산문) | **11.1 · 17.8 · 11.1초** | 1,450~1,962 |
| 개편 후 (샷별 라벨) | **8.7 · 16.7 · 10.5초** | 1,380~2,125 |
| 개편 후 + 생각 줄이기(LOW) | **7.1 · 7.7초** | 747~1,140 |
| (참고) `gemini-flash-lite-latest` = `gemini-3.5-flash-lite` | 1.1초 | 0 |

- **답을 짧게 만든 것만으로는 거의 빨라지지 않습니다.** 생각 시간이 지배하기 때문입니다.
- 이 수치는 클라우드 서버에서 프록시를 거쳐 잰 값이라 폰에서는 다를 수 있습니다. 경향만 보세요.

### 생각 줄이기 — 항목 이름을 찾는 데 실패가 많았습니다 (전부 400)

| 시도 | 결과 |
|---|---|
| `generationConfig.thinkingConfig.thinkingBudget = 0` | **400** (3.x 모델은 이 항목 없음) |
| `generationConfig.thinkingLevel = "low"` | **400** (위치가 틀림) |
| `generationConfig.thinkingConfig.thinkingLevel = "low"` (소문자) | 미확인(다른 이유로 429) |
| **`generationConfig.thinkingConfig.thinkingLevel = "LOW"` (대문자)** | **200 ✅ 이것만 통함** |
| `gemini-2.5-flash` 모델 지정 | **404** (이 키에서 더 이상 제공 안 됨) |
| lite 계열에 thinkingConfig | **400** (항목 자체를 모름) → 빼고 재시도 필요 |

→ 코드는 `thinkingLevel: "LOW"` 를 쓰고, **400이면 그 항목만 빼고 한 번 더** 보냅니다(lite 폴백 대비).

### ⚠️ 하마터면 낼 뻔한 사고 — `maxOutputTokens` 에 생각 토큰이 함께 잡힙니다

설계서 원안대로 `maxOutputTokens: 512` 로 두면, 모델이 생각에 490토큰을 쓰고
**답이 문장 중간에서 잘립니다** (`finishReason: MAX_TOKENS`).
실제로 이렇게 잘린 답이 나왔습니다: `[티샷] 내리막 포함 실거리 삼백미터 정도로 페어웨이 중앙 살`
→ **3072 로 올렸습니다.** 출력이 짧다고 상한을 낮추면 안 됩니다.
(이때 응답이 3~4초로 "빨라 보였던" 것은 생각이 잘려서였을 뿐 — 속도 개선이 아니라 고장입니다.)

### 결론

- 적용: 샷별 형식 + `thinkingLevel: LOW` + `maxOutputTokens: 3072` + 프레임 병렬 + 세션 캐시
  → **11~18초 → 7초대** (같은 모델, 같은 품질 등급 유지)
- **모델은 내리지 않았습니다.** lite 는 1.1초로 빠르지만 사장님 지시(퀄리티 우선)에 따라 폴백으로만.
- 더 빠르게 하려면 남은 수단은 **스트리밍**(6번 항목) 뿐입니다. 티샷 줄이 완성되는 즉시
  화면·음성에 내보내면 체감 2~3초가 됩니다. 지금 구조(줄 단위 라벨)가 그대로 이어집니다.
- 같은 홀 두 번째부터는 캐시로 **0초**입니다.

## 7. 검증 계획 (배포 전 필수)

1. **일부러 고장 내서 확인** (저장소 규칙): 라벨 누락 응답을 흘려 폴백(통짜 표시)이 도는지,
   400 응답을 줘서 thinkingConfig 재시도가 도는지, 라벨 수 불일치 재시도가 도는지 — 확인 후 원복.
2. `tools/sweep.js` 추가: `parseCaddie()` 파싱(정상·라벨누락·순서뒤섞임), `speechText()` 전처리,
   `pickKoVoice()` 목 보이스 검사(여성 우선·ko 없음 → 숨김 경로), 파별 라벨 목록 생성.
3. 화면 검증은 `elementFromPoint` 실터치 (CLAUDE.md 3-1) — 카드별 🔊·전체 듣기 포함,
   카드가 화면 밖으로 밀리지 않는지(`r.bottom <= innerHeight`)도.
4. 실기기: 아이폰(유나·제스처 해제·무음 스위치), 안드로이드 크롬 각 1회.
   파3·파4·파5 각 1홀 + 감곡CC 그린 있는 홀 1개. **실폰 확인 전 "완료" 보고 금지**.
5. 제공 범위(2-1장) 확인: ②유형 구장(OSM 홀 라인만 있는 곳)을 하나 열어
   AI 캐디 버튼이 사라지고 "준비중" 문구 + 위성 홀 뷰가 나오는지,
   ①등록 구장에서는 샷별 캐디가 정상인지, ③유형 배너도 그대로인지.
5. 배포는 `release_courses.py` + `verify_deploy.py --wait`.
