# 코스공략 AI 캐디 개편 설계 — "한 호흡 캐디" (2026-07-29, 클라우드 세션)

사장님 지시 요지 (2026-07-29):
1. **짧게** — 지금 공략은 너무 길다. 나이 드신 분들이 티박스에서 다 읽고 스윙하기 무리.
   군더더기 빼고, "싱글 골퍼님, 페이드 구질이시니 좌측 카트길 보고 과감히 스윙하세요! 좋은 결과가 있을 겁니다"
   처럼 **자신감을 심어주는 역할** 정도로.
2. **음성** — 글로도 보여주되, **밝고 자신감을 불어넣는 여성 음성**으로 바로 내레이션.
3. **속도** — 홀 이동하며 듣는 것이라 지금은 너무 오래 걸림. 답이 짧아진 만큼 빨리.
   단 **속도 때문에 퀄리티가 떨어지는 건 최악** — 퀄리티가 항상 우선.

구현은 로컬 오퍼스5가 진행. 이 문서는 그 작업 지시서다.

### 3~8초의 진짜 원인 (중요)

이미지도, 네트워크도 아니다. `gemini-flash-latest`(=2.5 Flash)는 **thinking이 기본으로 켜져 있고**,
여기에 4~6문장 출력을 요구하니 생성 시간이 길다. LLM 응답 시간은 대체로 출력 토큰 수에 비례한다.
→ **"짧게"라는 사장님 지시가 그 자체로 최대의 속도 개선이다.** 모델을 낮출 필요가 없다(퀄리티 우선 원칙과도 맞음).

## 2. 설계 A — 출력: "한 호흡 캐디" (2~3문장, 140자 이내)

### 형식

```
[1문장] 호칭 + 이 홀 티샷의 핵심 지시 하나 (구질 맞춤 조준점 + 클럽)
[2문장] 가장 큰 위험 하나를 피하는 법, 또는 세컨샷 핵심 하나
[3문장·선택] 자신감을 주는 격려 한마디
```

- 전체 **140자 이내** (음성으로 12~15초 — 티박스에서 딱 한 호흡).
- 존댓말, 기존 호칭 규칙("싱글 골퍼님" 등) 그대로.
- 구질 맞춤 조준점은 지금처럼 **필수** (이 앱 캐디의 정체성).
- "확인할 수 없는 정보는 지어내지 않는다" 원칙 그대로.
- 목록·번호·이모지 금지 (음성으로 읽을 문장이므로).

### 톤을 고정하는 예시 (프롬프트에 few-shot으로 1개 포함 권장)

- 싱글·페이드: "싱글 골퍼님, 미스가 적으시니 좌측 카트도로를 보고 드라이버로 과감하게 스윙하세요. 페이드가 페어웨이 중앙으로 돌아옵니다. 좋은 결과가 있을 겁니다!"
- 90대·슬라이스: "90대 골퍼님, 왼쪽 러프 끝을 보고 힘 빼고 부드럽게만 치세요. 오른쪽 벙커만 피하면 파 찬스입니다. 편하게 가시죠!"
- 입문자: "골퍼님, 페어웨이 한가운데만 보고 우드로 편하게 치세요. 왼쪽 연못은 쳐다보지 않으셔도 됩니다. 리듬만 지키면 충분해요!"

### 프롬프트 수정 지침

- 기존 프롬프트에서 **형식 문단만 교체**: "①티샷 ②세컨샷 ③그린 주변 순서로 4~6문장" →
  위 형식 + "정확히 2~3문장, 전체 140자 이내, 목록·이모지 없이".
- 형식 지시는 **프롬프트 맨 끝**에 둔다 (지시가 여러 개일 때 마지막 지시의 이행률이 높다).
- `playerTraitGuide()`의 "~한 줄 곁들이세요"류 문구들이 짧은 형식과 충돌한다 →
  각 문구를 "반영하되 **문장 수를 늘리지 말고 지시 문장 안에 녹이세요**"로 다듬는다.
  (예: 90대의 "힘 빼고 부드럽게"는 별도 문장이 아니라 티샷 지시에 합쳐지는 식 — 위 예시 참조)
- 캐릭터 한 줄 교체: "친절한 한국인 캐디" → "밝고 자신감 넘치는 투어 경력의 여성 캐디.
  플레이어에게 확신을 주는 말투" (음성 페르소나와 일치시킴).
- **길이 안전판**: 응답이 200자를 넘으면 "140자 이내" 지시를 앞뒤로 강조해 **1회만** 재시도.
  그래도 길면 그대로 표시한다 (자르거나 지어내지 않는다 — 퀄리티 우선).

### 상세 공략은? (사장님 결정 ①)

기본안: 한마디 캐디로 **완전 교체** (군더더기 제거 지시에 충실).
대안: 멘트 아래 "자세한 공략 보기" 접이 버튼으로 기존 4~6문장을 원할 때만 2차 호출.
→ 노출이 늘고 호출이 2배가 될 수 있어 기본안 권장. 필요해지면 그때 붙이는 게 싸다.

## 3. 설계 B — 음성: 기기 내장 TTS (Web Speech API)

### 왜 내장 TTS인가

| | 기기 내장 (speechSynthesis) | 클라우드 TTS (Google 등) |
|---|---|---|
| 비용 | **0원** | 과금 + 키 관리 |
| 지연 | **0초** (기기 안에서 합성) | 오디오 생성+다운로드 1~2초 추가 |
| 오프라인 | 대부분 동작 | 불가 |
| 품질 | 기기별 편차 (아이폰 유나는 준수) | 균일하게 높음 |

홀 이동 중 즉시 들려야 하고(속도 지시), 사용량 절약 원칙이 있으므로 **1단계는 내장 TTS**.
클라우드 TTS는 품질 요구가 커지면 2단계로 (OTA 제휴처럼 별도 과제).

### 여성 음성 선택 규칙 (`pickKoVoice()`)

```js
// 우선순위: 이름이 알려진 여성 한국어 음성 → 아무 ko 음성 → null(음성 기능 조용히 숨김)
const PREFER = ["Yuna", "유나",              // iOS·맥 기본 한국어 (여성)
                "Google 한국의",              // 안드로이드 크롬 (여성 톤)
                "Microsoft Heami", "Heami"];  // 윈도우
```

- `getVoices()`는 **첫 호출에 빈 배열**일 수 있다 → `voiceschanged` 이벤트에서 다시 고를 것.
- 밝은 톤: `utterance.pitch = 1.1`, `rate = 1.0~1.05` (기기별로 들어보고 확정).
- **ko 음성이 하나도 없으면**: 음성 버튼 자체를 숨기고 텍스트만. 오류·안내문 띄우지 않는다
  (틀릴 수 있는 정보는 표시하지 않는 원칙의 음성판 — 어색한 영어 억양으로 읽느니 침묵).

### 재생 흐름과 iOS 함정 (전부 실기기 검증 필요)

1. **iOS 제스처 잠금 해제**: 버튼 탭 핸들러 **안에서 동기적으로** 빈 문장을
   `speechSynthesis.speak(new SpeechSynthesisUtterance(""))` 한 번 실행해 오디오를 깨운다.
   응답 도착 후(비동기) 진짜 멘트를 speak — 이 선행 호출 없이는 iOS에서 무음이 될 수 있다.
2. **자동 재생**: 응답 표시와 동시에 재생 (홀 이동하며 듣는 용도이므로). 멘트 옆에
   `🔊 다시 듣기` / 재생 중 `⏹ 멈춤` 버튼.
3. **끄기 토글**: 설정에 "음성 캐디" on/off (`localStorage`, 기본 켬). 끄면 1번 선행 호출도 생략.
4. **정리(cancel)**: 새 홀 선택·화면 이동·새 요청 시작 시 `speechSynthesis.cancel()`.
   `renderImgCourse`의 `sel()`과 화면 전환부에 넣는다. 안 하면 이전 홀 멘트가 이어 나온다.
5. **iOS 무음 스위치**를 켜 두면 안 들릴 수 있다 — 앱이 감지할 방법이 없다.
   `🔊` 버튼이 있으니 별도 안내문은 넣지 않는다 (추측성 안내 금지).
6. 크롬의 "긴 문장 15초 후 멈춤" 버그는 140자면 해당 없음.

### 읽기 전처리 (`speechText()`)

- 이모지·괄호·따옴표 제거, `350m` → `350미터`, `파3` → `파 3`.
- 화면 텍스트와 음성 텍스트는 **같은 문장**을 쓴다 (전처리만 다름). 둘을 따로 생성하지 않는다
  — 호출 2배 방지 + "보이는 것과 들리는 것이 다르다" 문제 방지.

### 코드 배치

`js/app.js`의 AI 캐디 구역에 함수 3개(`pickKoVoice` `speechText` `speakCaddie`)로 충분 (~60줄).
새 파일을 만들면 `index.html` `<script>` 줄 추가가 필요한데, **index.html은 지금 로컬이 부킹
작업 중**이라 손대는 줄을 최소화하는 게 좋다. `#ai-strategy` 카드 주변(380행대)만 수정할 것
— 부킹 구역과 겹치지 않는지 수정 전 확인.

## 4. 설계 C — 속도 (퀄리티는 그대로, 낭비만 제거)

우선순위 순. ①②만으로 체감이 크게 달라진다.

| # | 처방 | 기대 효과 | 위험 |
|---|---|---|---|
| ① | `generationConfig`에 `thinkingConfig: { thinkingBudget: 0 }` 추가 | **가장 큼.** 2.5 Flash의 기본 thinking 제거. 짧은 캐디 멘트에 thinking은 불필요 | 모델·API판에 따라 400 거부 가능 → **400이면 thinkingConfig 빼고 즉시 재시도** (기존 모델 폴백 루프에 자연스럽게 얹기) |
| ② | 출력 축소 (설계 A) + `maxOutputTokens: 256` | 생성 시간 절반 수준 | 없음 (형식이 이미 140자) |
| ③ | 3D 프레임 fetch를 `Promise.all` 병렬로 (2420행) | 수백 ms | 없음 |
| ④ | 세션 캐시: `키 = 구장|코스|홀번호|프로필해시` → Map | 같은 홀 재탭 **0초** | 프로필 바꾸면 키가 바뀌므로 자동 무효화 |
| ⑤ | (보류) 다음 홀 프리페치 | 홀 이동 시 0초 | **공용 Gemini 무료 한도 소모 2배** — 사용량 절약 원칙과 충돌. 사장님 결정 ② |
| ✗ | 모델을 flash-lite로 내림 | — | **하지 않는다.** 퀄리티 우선 지시. lite는 지금처럼 폴백으로만 |

- 버튼 문구 `(3~8초)`는 개선 후 실측값으로 갱신 (근거 없는 숫자 금지).
- **개선 전 현재 소요 시간을 3회 실측해 기록**하고 시작할 것 (전/후 비교 없이 "빨라졌다" 보고 금지).
- 예상: 3~8초 → 1.5~3초. 예상일 뿐이므로 문서·화면에는 실측만 적는다.

## 6. 검증 계획 (배포 전 필수)

1. **일부러 고장 내서 확인** (저장소 규칙): 길이 안전판 검사에 300자 응답을 흘려 재시도가 도는지,
   `thinkingConfig` 400 폴백에 가짜 400을 줘서 재시도가 도는지 — 확인 후 원복.
2. `tools/sweep.js`에 추가: 캐디 멘트 형식 검사(문장 수·길이·이모지 없음, 실제 호출은 목으로),
   `speechText()` 전처리 단위 검사, `pickKoVoice()` 목 보이스 목록 검사.
   헤드리스는 보이스 0개일 수 있으므로 "없으면 버튼 숨김" 경로도 검사.
3. 화면 검증은 `elementFromPoint` 실터치 방식 (CLAUDE.md 3-1) — 새 🔊 버튼 포함.
4. 실기기: 아이폰(유나 음성·제스처 잠금 해제·무음 스위치), 안드로이드 크롬 각 1회.
   음성은 헤드리스로 검증이 안 되는 영역이 있다 — **실폰 확인 전에 "완료" 보고 금지**.
5. 배포는 `release_courses.py` + `verify_deploy.py --wait` (골프앱 표준 절차).

## 7. 구현 순서 (오퍼스5)

1. 현재 응답 시간 3회 실측 기록 → ①thinkingBudget ②프롬프트 교체+maxOutputTokens ③프레임 병렬화 → 재실측
2. 음성 3함수 + 🔊 버튼 + 설정 토글 + cancel 배선
3. 세션 캐시
4. WAIT 문구 정합(날씨 문구 제거 포함)
5. sweep 검사 추가 (고장 내서 확인 → 원복)
6. 배포 + verify + 실기기 확인
