## 1장. 질문 전수 감사 — "이 답이 어디에 쓰이나" (지시 2)

`js/clubfit.js`의 모든 문항을 엔진 코드까지 추적한 결과입니다.
**결론 먼저: 66개 문항 중 63개는 로직에 실제로 쓰입니다. 2개는 전혀 안 쓰이고, 1개는 반쪽만 쓰입니다.**

### ✖ 전혀 안 쓰이는 것 (2건)

| 문항 | 현재 상태 | 조치 |
|---|---|---|
| **구력** (공통 C1, `S.career`) | 프로필 저장·확인 화면 표시뿐. `engine()` · `ironEngine()` · `wedgeEngine()` · `putterEngine()` · `gripEngine()` 어디서도 읽지 않음 | **로직에 연결** (아래 규칙) |
| **성별** (`S.auto.sex`, 동의화면에서 자동) | "이미 알고 있어요" 카드에 표시만 | **carry7 추정에 연결** (아래) |

**구력 연결 규칙** (버리지 않고 살립니다 — 피팅에서 구력은 실제 의미가 있습니다):
- `lt3` (3년 미만): ① 헤드 관용성 가점 +8 (스윙이 아직 완성 전 — 미스 범위가 넓음)
  ② 결과에 고정 노트: *"구력 3년 미만은 스윙이 계속 변하는 시기입니다. 고가 커스텀보다
  보급·중고로 시작하고 1~2년 뒤 다시 맞추는 걸 권합니다"* → 단종(중고) 카드 노출 문턱을 85%→75%로 완화
  ③ 미스 경향 기반 보정(킥·오프셋)의 가점 폭 절반으로 — 미스 자체가 아직 유동적이라 응답 신뢰도가 낮음
- `gt10`: 미스 경향 보정 폭 그대로(응답 신뢰 높음). 별도 가점 없음.
- 각 규칙이 발동하면 **결과의 "이렇게 읽었습니다" 블록에 그 이유가 문장으로 나와야 합니다** (기존 원칙).

**성별 연결**: 7번 캐리 슬라이더에 **「모르겠어요」 칩 추가** (1차 설계 I1에 있었으나 미구현).
선택 시 평균타수·성별·연령대로 추정하고 결과 요약에 **"7번 캐리는 추정값 기준"** 을 명시.
추정표(대략값 — 결과에 '추정'임을 반드시 표기, 절대원칙 2):

| 평균타수 | 남성 | 여성 |
|---|---|---|
| 80대 이하 | 150 | 130 |
| 90대 | 140 | 120 |
| 100+ | 125 | 105 |
60대 이상은 −10m. 성별 미입력이면 남성 기준으로 두되 "성별 미입력 — 남성 기준 추정" 표기.

## 2장. 내 골프백 화면 (지시 1)

### 문제
"내 백에 저장" 버튼은 `localStorage riweather.mybag`에 저장하고 AI 캐디(`playerTraitGuide`)가 실제로 쓰지만,
**저장된 내용을 다시 볼 수 있는 화면이 앱 어디에도 없습니다.** 사용자는 저장이 됐는지, 뭐가 저장됐는지 알 길이 없습니다.
(유일한 흔적은 클럽 선택 타일의 "맞춤 완료" 배지뿐)

### 설계

**진입점 2곳** — index.html 허브 메뉴는 건드리지 않습니다(부킹 작업과의 충돌 회피 + 메뉴 수 유지):
1. **클럽 선택 화면(PICK) 상단**에 골프백 카드 — 항상 표시.
   - 저장된 클럽이 있으면: `🎒 내 골프백 — 드라이버 · 아이언 저장됨  [열어보기 ›]`
   - 비어 있으면: `🎒 내 골프백 — 아직 비어 있어요. 피팅을 마치고 저장하면 여기에 담깁니다` (버튼 없음, 안내만)
2. **결과 화면의 저장 완료 문구** 옆에 `[골프백 보기 →]` 버튼 추가 (저장 직후 확인 동선).

**화면 구성** — clubfit 내부의 새 화면(`BAG`)으로, `data-jump="bag"` 로 이동:
```
🎒 내 골프백
┌─────────────────────────────┐
│ 드라이버        7/30 저장    │   ← 클럽별 카드. 저장 안 된 클럽은
│ [교체 검토] 핑 G430 MAX 10K  │      "아직 안 맞췄어요 [맞추러 가기]"
│ 벤투스 블루 6S · 그립 MCC    │
│ 구질 판정: 슬라이스           │
│ [다시 맞추기]                │
├─ 아이언 / 웨지 / 퍼터 / 볼 … │
└─────────────────────────────┘
ℹ️ AI 캐디가 홀별 공략에서 이 클럽 기준으로 조언합니다.
   이 정보는 이 폰에만 저장됩니다.
[클럽 선택으로 ←]
```

**저장 데이터 보수 (같이 고쳐야 화면에 넣을 게 있습니다)** — `saveBag`/`saveBagPart`:
- `shapeD: S.shapeD` 는 **레거시 필드라 항상 null 저장** (실사용 버그). 구질 판정 `flightRead().n` 을 저장하도록 교체.
- 클럽별 저장 시각이 없음 → `bag.driver.ts` 처럼 **부위별 ts** 추가 (전체 `bag.ts` 는 유지 — AI 캐디 호환).
- keep 판정 시 `head: null` 저장 → 화면에는 "지금 클럽 유지" 로 표기 (null 노출 금지 — `tools/check_null_display.js` 대상).
- iron/wedge/putter 부위엔 그립이 저장 안 됨 → 부위별 `grip` 추가.
- **기존 저장분과의 호환**: 새 필드가 없으면 그 줄만 생략 (undefined 노출 금지).

**검증 (CLAUDE.md 3-1 필수)**: 골프백 카드·[다시 맞추기]·[골프백 보기] 버튼 전부
`elementFromPoint` 실터치 + `r.bottom <= innerHeight` 확인. `tools/clubfit_check.js` 에
"저장 → 백 열기 → 항목 확인 → 다시 맞추기" 동선 추가.

## 3장. 필드/스크린 반영 강화 (지시 3)

### 현재 상태
`venue` 문항은 이미 있지만 쓰임이 장식 수준입니다 — 드라이버·아이언 헤드에 +4점(전체 점수 규모 80~100점 대비 미미), 안내문 2줄.
**"넣었다"고는 할 수 있어도 "맞춤에 반영된다"고 하기 어렵습니다.**

### 왜 스크린 골퍼는 피팅이 달라야 하나 (결과 화면에 이 논리로 설명합니다)

스크린과 필드는 세 가지가 다릅니다. 각각이 스펙에 직접 연결됩니다.

1. **매트에서 칩니다.** 매트는 뒤땅을 용서합니다(솔이 미끄러져 공이 나감) — 스크린에서 "미스 없음"이라는
   답은 필드 기준으로 과대평가일 수 있습니다. 그리고 매트 충격은 잔디보다 손목·팔꿈치에 큽니다.
2. **런이 계산으로 나옵니다.** 센서가 캐리를 재고 런은 시뮬레이션 — 캐리 최적화가 곧 점수입니다.
   낮고 구르는 탄도의 이점이 필드보다 작습니다.
3. **거리 숫자의 출처가 다릅니다.** 스크린 화면 숫자(대개 토탈)를 자기 거리로 기억하는 골퍼가 많습니다.
   피팅의 출발점인 7번 캐리가 여기서 흔들리면 전부 흔들립니다.

### 규칙 (구현 사양)

**R1. 거리 출처 확인** — venue가 `screen`/`both`이고 carry7을 직접 입력했으면 **후속 칩 1개** 표시:
"그 거리는 어디서 보셨어요?" → `스크린 화면 숫자` / `필드 실측(캐디·GPS)` / `감`
- `스크린 화면 숫자` 선택 시 한 번 더: "캐리였나요, 토탈이었나요?" → `캐리` / `토탈` / `모름`
- `토탈`(또는 `모름`)이면 7번 기준 런 약 5~8m를 빼고 계산하고, 결과 진단 블록에
  **"스크린 토탈 ○○m → 캐리 약 ○○m로 환산했습니다 (7번 런 가정 6m)"** 처럼 가정을 그대로 밝힙니다.
  (절대원칙 2 — 단정 대신 가정 공개. 기존 "모르면 무엇을 가정했는지 밝힌다" 방침과 동일)

**R2. 아이언** — venue=screen일 때:
- `ironMiss === "none"` 이면 진단 블록에: *"매트는 뒤땅을 가려줍니다. 필드에서는 뒤땅이 나올 수 있는
  전제로, 솔이 너그러운 헤드에 가점했습니다"* + 관용성 가점 +4 → **+10으로 상향**.
- `bodyIssue`에 wrist가 있으면 그라파이트 가점 강화(+표시 문구: *"매트 충격은 잔디보다 손목에 큽니다"*).

**R3. 드라이버** — venue=screen일 때:
- 기존 "캐리 기준" 팁 유지.
- 저스핀(런 이득) 헤드 가점을 절반으로 — 스크린에선 런이 시뮬레이션이라 저스핀의 총거리 이득이 작고,
  캐리를 깎으면서까지 스핀을 줄일 이유가 없습니다. (why 문구 포함)

**R4. 웨지** — 기존 "필드 기준으로 맞췄습니다" 유지 + 한 줄 보강: *"매트에서 낮은 바운스가 편하게
느껴져도 필드 잔디에선 뒤땅이 됩니다 — 스크린 감각으로 바운스를 낮추지 마세요."*

**R5. 퍼터** — venue=screen이고 greenSpeed=unknown이면 "보통" 가정을 명시: *"스크린 퍼팅 매트
기준의 감각은 필드 그린과 다릅니다. 그린 빠르기는 '보통'으로 가정했습니다."*

**R6. 결과에 전용 섹션** — venue=screen일 때만 "**스크린 위주 골퍼님께**" 블록(위 '왜' 3줄 요지 + 발동한
규칙 요약)을 결과 하단에 추가. `both`는 규칙은 발동하되 이 블록은 생략(문서량 절제).

> R1~R6 전부 **발동 조건과 이유가 결과 화면에 문장으로 남는 것**이 요구사항입니다.
> 점수만 조용히 바꾸면 사장님 지시("이유를 분석해서 설명")를 충족하지 못합니다.

## 4장. 결과 화면 — 3문장 요약 + 접이식 상세 (지시 4)

### 문제
결과 분량이 드라이버 약 3,200자. 신뢰를 위해 쌓은 설명이 오히려 읽히지 않고 있습니다.

### 설계 — "요약은 다 보이고, 상세는 접는다"

**결과 최상단에 요약 블록(`cf-tldr`) 신설.** 판정 스탬프 바로 아래, 정확히 3문장 틀:

```
① 진단   "골퍼님은 7번 145m의 보통 스피드에, 아웃-인 궤도에서 페이스가 열려 맞는
```

- ①은 각 엔진의 진단 축에서 **가장 결정적인 신호 2~3개만** 골라 조립 (스피드는 항상 포함).

  백 화면에서 "왜 이 클럽이었는지"를 다시 보여줍니다.

**요약 아래는 1순위 추천 카드만 컴팩트하게 노출**(헤드·샤프트·그립 — 이름+스펙 한 줄), 나머지는 전부 접습니다:

| 섹션 | 기본 상태 |
|---|---|
| 판정 스탬프 + 3문장 요약 + 1순위 카드 | **펼침 (이것만 보면 끝)** |

| 대안·단종 카드 / 그래서 이 조합 / 달라지는 것 | 접힘 — "▸ 자세한 추천과 근거" |
| 다만 짚어드립니다 (주의) | **펼침 유지** — 신뢰의 근간이라 접지 않음. 단 3문단→핵심 1문단+접힘 2문단으로 압축 |

- 구현은 `<details>` 대신 기존 칩/버튼과 같은 커스텀 토글 권장(스타일 통일·sweep에서 상태 확인 용이).

- **기존 문장 자산은 버리지 않습니다** — 위치만 접힘으로 이동. 지시는 "짧게 요약해달라"이지 "설명을 없애라"가 아님.
- 검증: 접힌 섹션 토글의 실터치 확인 + 요약 3문장에 내부 용어(`fadeLate` 등)·undefined 누출 검사 추가.
