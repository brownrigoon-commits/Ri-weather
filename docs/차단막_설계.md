## 2. 먼저 정직하게 — 골팡과 우리는 구조가 다르다

골팡이 우리를 막을 수 있었던 건 **서버가 있어서**다. 요청마다 세션·리퍼러를 보고
가짜 점검 페이지를 돌려줬다. 우리는 GitHub Pages **정적 호스팅**이라 서버 코드가
한 줄도 없다 — 누가 요청했는지 보지도, 골라서 거절하지도 못한다.

그래서 이 설계의 결론은 세 겹이다:
- **정적 데이터** → 완전 차단은 불가. 대신 ①법적 방벽 ②복제 증거(카나리) ③2단계에서 프록시 차단
- **백엔드(돈 나가는 곳)** → 여기는 서버가 있으므로 **실제 차단 가능**. 최우선.
- **하지 않는 것** → 우클릭 금지·개발자도구 감지·난독화. 전부 5분이면 우회되고
  진짜 유저 경험만 해친다. 겉만 차단막인 것은 만들지 않는다.

## 3. 위협 순위 (피해 크기 순)

1. **백엔드 도용** — 소스에서 Apps Script URL을 뽑아 `fn=tts` 를 반복 호출하면
   **우리 구글 계정 요금**이 나간다. 지금은 아무 검사가 없다. ← 실측 확인
2. **DB 통째 복제** — 경쟁 앱이 holeimgdb·golfdb 를 그대로 들고 가는 것.
   골팡 판례(서울중앙지법 2018가합508729, 배상 10억)가 우리 편이 되는 지점.
3. **AI/검색 봇 수집** — robots.txt 전면 차단 완료(2026-07-30). 신사협정 수준.
4. **핫링크** — 남의 사이트가 우리 홀맵 이미지를 직접 걸어 쓰는 것.

## 4. 단계별 설계

### 0단계 — 이미 되어 있는 것
- `robots.txt` 전면 차단 (GPTBot·ClaudeBot 포함 전 봇)
- API 키는 전부 Apps Script Script Properties — 소스에 키 없음
- 백업 데이터는 12자리 코드 없이는 조회 불가

### 1단계 — 지금 바로 할 수 있는 것 (승인 시 구현)

**A. 백엔드 문고리 (최우선 — 돈이 걸린 곳)**
Apps Script 쪽에서:
- `fn=tts`: 텍스트 200자 상한 + **일일 호출 상한**(CacheService 카운터, 예: 하루 3,000회
  넘으면 그날 중단) + 캐시 우선(같은 문장 재합성 금지 — 이미 일부 있음)
- `fn=placemeta/placephotos`: 일일 상한 + 결과 캐시 수명 연장
- 앱→백엔드 요청에 **날짜 기반 서명 토큰** 추가, 백엔드에서 대조.
  *정직한 한계: 토큰 생성식도 앱 소스에 보이므로 작정한 공격자는 못 막는다.
  막는 것은 "URL만 복사해 돌리는 스크립트 남용"이다. 그래도 일일 상한이
  최후 방어선이라 최대 피해액이 상한으로 고정된다.*

**B. 법적 방벽 (골팡이 이긴 그 무기)**
- `js/legal.js` 약관에 조항 추가: 무단 크롤링·복제·재배포 금지, 저작권법 제93조
  **데이터베이스제작자 권리** 명시(상당한 투자로 제작·검증한 DB), 부정경쟁방지법
  데이터 부정사용 금지, 위반 시 법적 조치.
- 데이터 파일(`golfdb.js`·`holeimgdb.js`·`coursevideos.js`·`bookingids.js`) 머리에
  저작권·무단수집 금지 고지 한 줄. *골프장DB는 OSM(ODbL) 유래분과 우리 추가분을
  구분해 표기해야 한다 — ODbL 부분은 우리도 공유 의무가 있다.*

**C. 복제 증거 — 카나리**
지도 회사들이 가짜 골목(trap street)으로 복제를 증명하듯, 우리 DB에만 있는
표식을 심는다. 남의 서비스에서 이 표식이 발견되면 "우리 것을 복사했다"는 증거가 된다.
- ⚠️ **신뢰 원칙(틀릴 수 있는 정보는 표시하지 않는다)을 절대 깨지 않는 방식으로만**:
  가짜 구장·가짜 홀은 만들지 않는다. 대신
  ① 화면에 표시되지 않는 여분 필드(예: 내부 정렬키)에 고유 서명값
  ② 홀맵 이미지 몇 장에 눈에 안 보이는 픽셀 워터마크
  ③ 카나리 목록은 저장소가 아닌 `.secrets/` 에만 기록(저장소에 두면 베끼는 쪽도 본다)

**D. 핫링크 대응**
GitHub Pages 는 Referer 차단이 불가 → 이미지 자체에 흐린 출처 표기를 넣는 것만
가능한데, 홀맵 가독성을 해치므로 **2단계(Cloudflare 핫링크 보호)로 미룬다.**

### 2단계 — tourlist 도메인을 살 때 (리브랜딩과 한 묶음)
도메인을 사서 **Cloudflare(무료 플랜)를 앞에 세우면** 그때부터 골팡처럼 서버 수준
차단이 가능해진다:
- 봇 차단(Bot Fight Mode) · 국가별 차단 · **레이트리밋**(같은 IP가 초당 수십 회 요청하면 차단)
- 핫링크 보호(우리 페이지에서만 이미지 로드 허용)
- 특정 경로(js/holeimgdb.js 등) 이상 트래픽 알림
어차피 리브랜딩에 도메인이 필요하므로, **도메인 구매 시점 = 차단막 2단계 시점**으로 잡는다.

### 3단계 — 사업화(데이터 제휴를 팔게 될 때)
정적 파일에서 **API 서버**(키 발급제)로 옮긴다. "아직은 안 넘기지만 나중엔 모르겠다"
하신 그 나중이 오면, 이 단계가 곧 상품이 된다.

## 5. 하지 않는 것 (그리고 이유)
| 안 하는 것 | 이유 |
|---|---|
| 우클릭·복사 금지 스크립트 | 개발자도구로 5분 우회. 유저 불편만 남는다 |
| 개발자도구 감지 | 오탐으로 정상 유저가 막힌다. 우회도 쉽다 |
| JS 난독화 | 데이터(JSON)는 난독화해도 실행하면 그대로 나온다. 디버깅만 어려워진다 |
| 가짜 구장 카나리 | 유저에게 틀린 정보를 보여주게 된다 — 신뢰 원칙 위반이라 금지 |

## 6. 결정해 주실 것
1. **1단계 구현 승인** — A(백엔드 문고리)·B(법적 방벽)·C(카나리) 바로 작업 가능.
   특히 A는 돈이 걸려 있어 먼저 하는 것을 권한다.
2. 2단계 시점 — tourlist 도메인 구매를 언제 할지 (리브랜딩 일정과 묶임)
