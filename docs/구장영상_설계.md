## 1. 결정적 사실 — 할당량은 두 버킷이다

공식 문서 원문으로 확인했다. 이걸 모르면 설계가 통째로 틀린다.

| 버킷 | 한도 | 무엇이 쓰나 |
|---|---|---|
| **검색 전용** | **하루 100회** | `search.list` (1회 = 1건) |
| 일반 | 하루 10,000 units | `playlistItems.list`·`videos.list`·`channels.list` (각 1 unit) |

→ **`playlistItems.list` 로 채널 업로드를 몇천 편 훑어도 검색 횟수가 줄지 않는다.**
채널당 1,000편이어도 20 units. 10개 채널 전량 스캔이 200 units(10,000의 2%)다.

**키는 무료다.** 빌링 등록 불필요, 심사 없음(기본 할당량 범위 내).

## 3. 수집 절차와 비용

| 단계 | API | 소모 | 버킷 |
|---|---|---|---|
| ① 채널ID 확정 | channels.list | 10 units | 일반 |
| ② 업로드 전량 스캔(10채널) | playlistItems.list | 200 units | 일반 |
| ③ 못 채운 구장 보충 검색 | **search.list** | 구장당 1~2회 | **검색 100/일 ← 유일 병목** |

**①②④는 하루에 끝난다**(합계 300 units). 소요일수 = `남은구장 × 검색어수 ÷ 100`.
채널 크롤 커버율 C 에 따라 C=0.6 이면 **3일**, C=0 이면 7~9일.

> **본실행 전 샘플검증**: 1일차에 **채널 크롤만 돌려 커버율 C 를 실측**하고 그 숫자로 일정을 정한다.

## 4. 🔴 30일 보관 규정 — 갱신 자동화가 필수

개발자 정책 원문:
> *"an API Client must not store statistics retrieved as Non-Authorized Data for more than 30 days."*

우리는 OAuth 없는 공개 조회 = Non-Authorized. **조회수는 예외 없이 30일**이다.
→ **2주 주기 자동 갱신**을 GitHub Actions 로 건다(`.github/workflows/golfrules.yml` 전례가 있다).
갱신은 검색을 안 쓰고 85 units 이라 비용이 사실상 0이다.
**갱신이 멈춘 목록 파일을 그대로 두는 것 자체가 정책 위반**이므로, 갱신 실패 시 알림도 함께 건다.

  기준일을 함께 찍는다.
- **III.E.4.h** API 데이터로 **파생 지표를 만들어 표시하면 안 된다** → 조회수·좋아요를 섞은
  자체 '공략 점수'를 화면에 노출하지 않는다. *(내부 정렬에만 쓰는 것이 걸리는지는 **유권해석 미확인** —
  §8 법률 확인 항목.)* 안전한 기본값은 **조회수 그대로 정렬**이다.
- 출처 표기 의무(ToS 10.3) → 유튜브 로고/"YouTube에서 보기" 링크를 붙인다.

## 5. 검색어 — 한국과 일본이 **정반대**다

| 국가 | 쓸 것 | 쓰면 안 되는 것 |
|---|---|---|
| 🇰🇷 한국 | `{구장명} 코스공략` · `{구장명} {코스명} 공략` · `{구장명} N번홀` | **`{구장명}` 단독** · `{구장명} 라운딩` — 1위가 브이로그로 고정됨(파주CC 508,531회짜리 백돌이 영상) |
| 🇯🇵 일본 | **`{구장명}` 단독**(반환 10건 전부 적중, 오염 0) · `{구장명} ホール攻略` | `コース攻略` — 일본 유튜브 제목에 거의 안 쓰인다 |

**하나의 규칙으로 424곳을 돌리면 안 된다.**
공통: `type=video`, `maxResults=50`, `videoEmbeddable=true`, 한국 `regionCode=KR&relevanceLanguage=ko`,
일본 `regionCode=JP&relevanceLanguage=ja`, `order=relevance`.
`order=viewCount` 는 **쓰지 않는다** — 조회수 1위가 브이로그로 고정되는 게 실측으로 확인됐다.
어차피 50건 받아 우리가 재정렬한다.

## 6. 오탐 필터 — 4단 게이트 (이게 없으면 못 쓴다)

제목·설명을 정규화(`컨트리클럽|골프클럽|골프장|CC|GC` 제거, 일본어는 `ゴルフ倶楽部|カントリークラブ` 제거
+ 전각→반각)한 뒤:

| 게이트 | 규칙 | 실제로 잡은 것 |
|---|---|---|
| **G1 필수 포함** | 구장 핵심어가 제목·설명에 없으면 탈락 | 무관 영상 대량 제거 |
| **G2 타 구장 우선권** | 등록 구장명 사전과 대조해 **다른 구장명이 제목에 있으면 탈락** | `[전백시] 중원CC 베테랑 캐디…신라코스`(25,939회)를 신라CC에서 제거 |
| **G3 지역 게이트** | 핵심어가 짧거나 동명 충돌이면 **지역 토큰(여주/경주…)이나 코스명이 함께 있어야 통과**. 없으면 사람 판정 큐로 | 여주 신라CC ↔ 경주 신라CC 반반 섞임 |

⚠️ **별칭(구 명칭) 필드가 필수다.** `스카이72→클럽72` 처럼 개명한 구장은 **옛 이름 영상의 조회수가 더 높고**,
제목에 `구.스카이72` 를 병기한다. 별칭도 G1 의 유효 토큰으로 인정한다.

⚠️ 상위 3~5개만 **사람이 훑는 검수 단계**를 넣는다. 424곳×10개=4,240건 전량 검수는 비현실적이다.

## 7. 저장·화면

**생성물 파이프라인** — 홀맵 DB·부킹 번호표와 같은 방식.
```
tools/build_coursevideos.py   (로컬에서만 API 키 사용)
        ↓
js/coursevideos.js            (생성물 — 직접 고치지 말 것)
```
⚠️ **키를 앱에 넣으면 안 된다.** 정적 사이트라 즉시 유출되고 하루 100검색이 남에게 소진된다.

담을 항목: `videoId · title · channel · views · likes · duration · publishedAt · kind(hole|course|round) · holeNo?`
+ 파일 전체에 `fetchedAt`(기준일, 화면 표기용).

**화면** — 코스공략의 홀 3D 영상 아래.
1. 그 홀 영상이 있으면 **홀 영상 우선**
2. 없으면 그 코스 영상 → 그것도 없으면 구장 전체 영상
3. 아무것도 없으면 **지금처럼 유튜브 검색 링크**(폴백 유지 — 없는 걸 있는 척하지 않는다)

**일본에서의 값어치**: 홀맵 그림이 없는 구장은 지금 "코스공략 준비중"만 뜬다.
여기에 영상 목록이 들어가면 **그 화면이 비지 않는다.** 홀맵 400곳 상한의 빈자리를 메우는 수단이다.
