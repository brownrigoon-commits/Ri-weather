### 오늘 잡은 버그 하나 (다시 나지 않도록 테스트까지 넣었습니다)

첫 수집은 **실패**했습니다. 수집·출고점검은 다 통과했는데 **커밋·푸시**에서 죽었습니다.

원인: 그 시각에 사장님이 골프앱 v126 을 push 하셔서 원격이 앞서 있었고 →
푸시가 거부되어 리베이스로 넘어갔는데 → **리베이스에 git 신원을 안 넘겨서**
`fatal: empty ident name` 으로 죽었습니다. 20분 걸려 모은 데이터가 날아갔습니다.

`git commit` 에는 `-c user.name=…` 을 넘겼는데 리베이스에는 빠뜨린 것이 원인이었습니다.
리베이스도 커밋을 새로 만드는 작업이라 신원이 필요하고, 깃허브 러너에는 그게 비어 있습니다.
**두 PC 를 동시에 쓰는 이 저장소에서 "원격이 앞선 상태"는 예외가 아니라 일상입니다.**

고친 뒤 다시 돌려 성공했습니다. 재현 테스트(`test_publish_rebase.py`)를 넣었고,
고친 부분을 되돌리면 **실제로 실패하는 것까지 확인**했습니다.
