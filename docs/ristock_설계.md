# Ri_Stock 설계 규격 (v1)

> 이 문서는 **엔진(Python) · 프런트(PWA) · 자동화(CI)** 세 파트가 공유하는 계약서입니다.
> 필드 이름 하나만 어긋나도 화면이 비어 보이므로, 구현 전에 이 문서를 먼저 맞춥니다.

## 0. 무엇을 만드는가

사장님이 이미 만들어 둔 두 프로그램을 **자동으로 돌아가는 앱**으로 바꿉니다.

| 기존 | 문제 | 바뀌는 모습 |
|---|---|---|
| `기업분석표_생성.py` (수동 실행 8분) | 사람이 켜야 함 | 매일 자동 실행 (GitHub Actions + PC 예약) |
| `주식_대시보드/app.py` (Flask localhost:8500) | PC에서만, 로그인 필요 | GitHub Pages PWA — 폰에서 바로 |
| 대시보드가 xlsx를 파싱 | 엑셀 서식 바뀌면 깨짐 | 엔진이 JSON을 직접 산출 |
| 매일 같은 화면 | 어제와 뭐가 달라졌는지 모름 | 전일 대비 신규 편입/이탈 자동 표시 |

**절대 바뀌면 안 되는 것**: 점수 체계(13항목 112점 → 100점 환산)와 전략 8종의 종목 선정 결과.
기존 `cache/strategy_*_20260716.json` 8개가 정답지이며, 새 엔진은 이를 **그대로 재현**해야 합니다.

## 1. 파일 배치

```
ristock/                            ← GitHub Pages 공개 경로 /Ri-weather/ristock/
├── index.html  css/  js/  sw.js  manifest.webmanifest  icons/
├── data/                           ← 자동 생성물 (엔진이 만들고 CI가 커밋)
│   ├── manifest.json               최신 데이터 인덱스 (앱이 가장 먼저 읽음)
│   ├── market.json                 10개국 뉴스 → 시장 분위기·섹터 순위
│   ├── stocks_KR.json              한국 종목 (시총 300 + 평가 상세)
│   ├── stocks_US.json              미국 종목
│   ├── strategies.json             전략 정의 + 섹터 매핑표
│   ├── changes.json                전일 대비 신규 편입/이탈
│   └── picks_baseline.json         변화 계산용 기준선 (엔진 전용 · 앱은 읽지 않음)
└── engine/                         ← Python 엔진
    ├── config.py scoring.py news.py sources_us.py sources_kr.py
    ├── analyze.py emit.py strategies.py excelout.py
    ├── pipeline.py publish.py seed_from_xlsx.py
    ├── requirements.txt
    └── tests/  (fixtures 포함, 네트워크 없이 실행)
```

앱은 **항상 날짜 없는 최신 파일**만 읽습니다(캐시 무효화는 `?v=생성시각`).

`--archive` 를 주면 날짜별 원본이 `ristock/data/archive/YYYYMMDD/` 에도 복사됩니다.
이 폴더는 **저장소에 올리지 않습니다**(`.gitignore`) — 사장님 PC 에서 되짚어 볼 때 쓰는 로컬 사본입니다.

> ⚠️ 예전에는 이 폴더를 매 회차 커밋했습니다. 한 회차 0.6MB × 하루 두 번이면
> **연 40MB**(압축 후)이고, git 이력은 append-only 라 나중에 지워도 영원히 남습니다.
> 이미 837MB 인 저장소를 집·회사 두 PC 가 매번 clone·pull 하므로 그 워크플로가 직접 느려집니다.
> 커밋해야 할 이유는 딱 하나 — `changes.json` 의 비교 대상 — 이었는데,
> 그건 아래 `picks_baseline.json`(약 20KB) 하나로 충분합니다.
> GitHub Actions 러너는 매번 새로 만들어져 archive 가 남지도 않으므로,
> CI 는 그동안 아무도 읽지 않는 파일을 커밋만 하고 있었습니다.

## 2. 데이터 규격

### 2.1 `manifest.json`

```json
{
  "데이터버전": 1,
  "생성시각": "2026-07-16 13:48",
  "기준일": "20260716",
  "고지": "본 자료는 … 투자 권유가 아닙니다. …",
  "시장": {
    "한국": { "파일": "stocks_KR.json", "종목수": 300, "평가종목수": 152,
              "원본": "한국_기업_분석표_자동_20260716.xlsx", "수집시각": "2026-07-16 13:48",
              "수집주체": "pc" },
    "미국": { "파일": "stocks_US.json", "종목수": 300, "평가종목수": 148,
              "원본": "미국_기업_분석표_자동_20260716.xlsx", "수집시각": "2026-07-16 13:43",
              "수집주체": "github-actions" }
  },
  "실행": { "주체": "github-actions" | "pc", "성공": true, "메모": "" }
}
```

**`시장.<시장>.수집주체` (2026-07-28 추가)** — 그 시장을 **누가 받아왔는지**(`pc` / `github-actions`).
최상단 `실행.주체` 는 마지막 회차 한 번의 주체일 뿐이라, 시장마다 다를 수 있는 실제 출처를 잃습니다.

한국 재무·수급은 네이버금융에서 받는데 네이버는 해외(깃허브) IP 를 막을 수 있어
**한국은 국내 PC 가 주담당, 미국은 깃허브가 주담당**입니다(둘 다 서로의 백업으로 양쪽을 수집).
워크플로는 이 값을 보고 *오늘 한국을 이미 국내 PC 가 받았으면 한국 수집을 건너뜁니다* —
해외에서 받은 한국 데이터가 국내에서 받은 것을 덮어쓰지 않게 하기 위함입니다.

시장 하나가 실패하면 **그 시장만 이전 데이터를 유지**하고 `성공: false` + 메모를 남깁니다.
(부분 실패로 멀쩡한 데이터를 덮어쓰지 않습니다.)

`시장.<시장>.기준일` 은 **시장마다 따로** 들고, 최상단 `기준일` 은 그중 **가장 오래된 값**입니다.
한국만 며칠 멈춰 있을 때 최상단에 오늘을 찍으면 앱이 "오늘 데이터"라고 거짓말을 합니다.

> ⚠️ 그래서 **`stocks_XX.json` 의 기준일은 최상단이 아니라 `시장.<시장>.기준일` 과 비교**해야 합니다.
> `tools/ristock_출고점검.py` 가 최상단과 비교하던 시절, 한국만 실패한 날마다
> 멀쩡히 수집된 미국 데이터가 게이트에 걸려 아예 배포되지 못했습니다.

`고지` 는 투자 권유가 아니라는 한 줄입니다. `ristock/data/*.json` 은 공개 주소로 그대로 열리므로
앱 화면을 거치지 않는 사람에게도 보이도록 `manifest.json` · `stocks_XX.json` 양쪽에 넣습니다.

#### `차트` (2026-07-29 추가) — 종목 상세의 주가 그래프

파일 **맨 위에 한 번만** 담습니다(종목 레코드 안이 아닙니다).

```json
"차트": {
  "일": { "날짜": ["20260429", …60개],
         "종목": { "005930": [70500, …60개], "000660": [ … ] } },
  "주": { … 52개 }, "월": { … 24개 }, "연": { … 10개 }
}
```

- **왜 파일에 담나**: 앱은 정적 페이지라 브라우저에서 주가 API 를 직접 못 부릅니다
  (2026-07-28 확인: 야후 chart·stooq 모두 CORS 차단 `Failed to fetch`).
  엔진은 점수 계산을 위해 어차피 2015년부터의 일별 종가를 받으므로 그것을 줄여 담습니다.
- **날짜축은 시장당 한 벌**입니다. 종목마다 날짜를 되풀이하면 하루 두 번 커밋되는
  이 저장소가 그만큼 무거워집니다. 종목별로는 **값 배열만** 담고 축에 자리를 맞춥니다.
- **담는 종목은 평가 종목만**입니다(한국 144 · 미국 110 안팎). 실측 증가량은
  한국 +158KB · 미국 +125KB(합계 약 +283KB/회차).
- 값이 없는 자리는 `null` 입니다(상장 전·거래정지). **0 으로 채우지 않습니다** —
  그래프가 바닥까지 떨어진 것처럼 보입니다. 화면도 그 구간의 선을 끊어 그립니다.
- **날짜는 반드시 실제 거래일**입니다. `resample().last()` 로 만들면 값은 맞아도
  날짜가 구간 끝으로 바뀌어 7/28 종가가 `2026-12-31`(연말)·일요일로 찍힙니다.
  아직 오지 않은 날짜가 화면에 나가면 그건 틀린 정보입니다(`test_charts.py` 가 지킵니다).
- 주가 원본이 그날 종가를 아직 안 채웠으면 그래프가 기준일보다 하루 짧아질 수 있습니다.
  화면은 그 사실을 카드 아래에 적습니다(값을 지어내지 않습니다).

### 2.3 `market.json`

기존 `cache/summary_YYYYMMDD.json` 형태에 **`지수`** 한 칸을 더한 것입니다.

```json
{ "날짜": "2026-07-16 11:44", "요약": "[07.28 종가] 코스피 6,023.66 (-10.8%) … 오늘 10개국 …",
  "지수": { "수집시각": "2026-07-28 22:13", "급락기준": -3.0, "실패": [],
           "목록": [ {"시장":"한국","이름":"코스피","코드":"KS11",
                     "날짜":"20260728","종가":6023.66,"등락률":-10.84} ] },
  "국가별": { "미국": {"수집":58,"긍정":12,"부정":9}, "…": {} },
  "섹터순위": [ {"순위":1,"섹터":"AI·반도체","점수":38.5,"뉴스수":31,
                "긍정":16,"부정":3,"대표뉴스":["(미국) …"]} ],
  "주요뉴스": [ {"국가":"한국","제목":"…","뉘앙스":1,"섹터":["AI·반도체"]} ] }
```

**`지수` (2026-07-28 추가)** — 코스피·코스닥·S&P500·나스닥의 최근 종가와 전일대비 등락률.
국내 소스(FinanceDataReader)에서 받습니다. 야후를 거치지 않으므로 해외 IP·인증서 문제와 무관합니다.

- **왜 넣었나**: 분위기를 뉴스 건수만으로 정하던 때, 코스피가 −10.8% 빠진 날에도
  화면에 `중립·혼조` 가 떴습니다. 뉴스는 하루 종일 고르게 쌓이지만 지수는 그날 하루가
  그대로 찍힙니다. 그래서 **`요약` 첫 문장은 지수가 정합니다**(지수를 못 받으면 예전처럼 뉴스가 정함).
- **판정**(`news.지수_반영_분위기`, 한국 지수 평균 기준):
  `≤ −3%` 급락 · `≤ −1%` 약세 · `≥ +3%` 급등 · `≥ +1%` 강세 · 그 사이는 보합.
- **`날짜`** 는 그 값이 **어느 날 종가인지**입니다. 07:00 회차에는 한국 장이 열리기 전이라
  코스피가 어제 종가로 담깁니다 — 화면은 이 날짜를 반드시 함께 보여 줍니다(신뢰 우선).
- **`급락기준`** 을 파일에 함께 담는 이유: 화면(`app.js 급락경고배너`)이 이 값을 읽습니다.
  양쪽에 숫자를 각각 적어 두면 한쪽만 고쳤을 때 요약 문구와 경고가 조용히 갈라집니다.
- 목록이 비어 있어도(수집 실패) 앱은 그대로 동작합니다 — 지수 카드와 경고만 사라집니다.
- **전략 계산은 이 칸을 쓰지 않습니다.** 전략이 보는 것은 `섹터순위` 뿐입니다(3.3).
  즉 지수를 넣어도 정답지(전략 선정 결과)는 달라지지 않습니다.

### 2.5 `changes.json`

```json
{ "기준일":"20260716", "이전기준일":"20260715",
  "전략별": { "total": { "한국": { "신규":[{"티커","기업명","섹터"}], "이탈":[…] } } } }
```

앱은 `manifest.변화파일`(또는 `manifest.이전기준일`)이 있을 때만 이 파일을 읽습니다(`js/data.js`).
그래서 **파일을 실제로 만든 회차에만** 그 키를 넣습니다 — 없는 파일을 가리키면 404 가 쌓입니다.

만드는 규칙은 세 가지입니다.

1. 비교는 **티커 집합**으로 합니다. 같은 종목이 다른 섹터 블록으로 옮겨간 것은 신규·이탈이 아닙니다.
2. 비교할 어제(=`picks_baseline.json`)가 없으면 **파일을 만들지 않습니다.**
   전부 '신규'로 표시하면 첫날 화면이 통째로 새 종목처럼 보입니다.
3. **오늘 갱신된 시장만** 담습니다. 수집이 실패해 어제 파일이 그대로 남은 시장을 넣으면
   자기 자신과 비교해 "변화 없음"이 나오는데, 그것은 "오늘 갱신됐는데 변화가 없다"와 전혀 다릅니다.
   (갱신 여부는 `stocks_XX.json` 의 기준일이 오늘인지로 판단합니다. 그래서 CI 처럼
   `--market us` · `--market kr` 를 따로 도는 날에도 나중 회차가 아침 회차의 결과를 지우지 않습니다)

### 2.6 `picks_baseline.json` — 변화 계산의 비교 대상 (엔진 전용)

`changes.json` 을 만들려면 **어제 무엇을 뽑았는지**가 필요합니다.
그 목적에 스냅샷 전체(0.6MB)는 필요 없습니다. 전략별 추출 결과(티커 목록)면 충분합니다.

```json
{ "기준일": "20260726",
  "전략별": { "total": { "한국": [{"티커","기업명","섹터"}], "미국": [ … ] }, "…": {} },
  "시장기준일": { "한국": "20260726", "미국": "20260726" },
  "대기": { "기준일": "20260727", "전략별": { … }, "시장기준일": { … } } }
```

| 칸 | 뜻 |
|---|---|
| `기준일` · `전략별` | **비교 기준(= 어제) 몫.** `changes.json` 의 `이전기준일` 이 여기서 나옵니다 |
| `시장기준일` | 시장마다 마지막으로 갱신된 날 (한쪽만 며칠 멈춰도 정직하게 적기 위해) |
| `대기` | **오늘 뽑은 몫.** 날짜가 바뀐 다음 회차에서 비교 기준으로 승격됩니다 |

동작 규칙:

- 기준선의 날짜가 **오늘보다 이전인 시장만** 비교합니다.
- `대기` 를 따로 두는 이유: 오늘 몫을 곧바로 비교 기준에 덮어쓰면, 하루에 두 번 도는 날의
  두 번째 회차가 '어제'가 아니라 '오늘 아침'과 비교하게 됩니다.
  사장님이 보고 싶은 것은 언제나 **어제 대비**입니다.
- 승격·갱신 모두 **시장 단위로 겹칩니다.** 그날 수집이 실패한 시장의 기준은 덮지 않고 그대로 둡니다
  (다음에 성공했을 때 마지막으로 성공한 날과 제대로 비교되어야 합니다).
- 기준선이 없으면(첫 실행) `changes.json` 을 만들지 않고 manifest 에도 키를 넣지 않습니다.
  그래서 이 방식으로 바꾼 **첫날은 하루 종일**(그날 두 회차 모두) 변화 카드가 뜨지 않고,
  **다음 날 첫 회차부터** 정상으로 나옵니다.
- 기준선이 망가졌으면(JSON 이 깨졌거나 어느 한 칸의 타입이 어긋났으면) **그 칸을 버리고
  그 회차가 새로 만듭니다.** 예외로 끝내면 기준선을 다시 쓰지 못해 손상이 굳고,
  사람이 파일을 지울 때까지 변화 카드가 다시는 안 뜹니다(`emit._칸`).
- 기준선 날짜가 오늘보다 **미래**면(시계 오류 등) 그 시장은 비교하지 않습니다.
  다음 회차의 `대기` 승격이 그 값을 덮어써 저절로 풀립니다.

크기는 하루치 약 10KB, 어제+오늘 두 벌을 들고 있어 **파일 전체 약 20KB** 입니다.
예전 방식(회차당 0.6MB 커밋)의 3% 이고, 앱은 이 파일을 읽지 않습니다.

## 3. 전략 엔진 규칙 — Python·JS 양쪽 동일

전략 계산은 **프런트(JS)가 정본**입니다. 사장님이 폰에서 필터를 바꾸면 즉시 다시 계산되어야 하기 때문입니다.
Python 쪽은 엑셀 내보내기·`changes.json` 산출·테스트에만 같은 규칙을 씁니다.
두 구현은 아래 규칙을 **글자 그대로** 따릅니다.

### 3.1 필터 (`filters`) — 모두 AND

| 키 | 통과 조건 |
|---|---|
| `악재제외` | `악재` 가 빈 문자열 |
| `흑자만` | `근거.재무` 에 `"흑자"` 포함 |
| `눌림만` | `근거.차트` 에 `"눌림"` 포함 **그리고** `"미눌림"` 으로 시작하지 않음 |
| `전고점돌파만` | `지표.고점대비 >= 85` **그리고** `지표.10일고점비 > 0` (둘 중 하나라도 null이면 탈락) |
| `미네르비니만` | `미네르비니 === "O"` |
| `거래량150이상` | `지표.거래량비 >= 150` (null은 0으로 보아 탈락) |
| `순익성장25이상` | `지표.순익성장률 >= 25` (null은 탈락) |
| `신고가근접만` | `지표.고점대비 >= 75` (null이면 탈락) |

### 3.2 순위 기준 (`rank_by`)

| 값 | 1차 키 | 2차 키 |
|---|---|---|
| `총점` | `총점` | `총점` |
| `차트` | `점수.차트` | `총점` |
| `모멘텀` | `점수.모멘텀` | `총점` |
| `전고점` | `지표.고점대비` | `지표.10일고점비`, 그다음 `총점` |
| `마법공식` | `마법공식점수` | `총점` |

모두 **내림차순**, null은 0으로 취급, **동점이면 입력 배열 순서 유지(안정 정렬)**.

`마법공식점수` = `-(이익수익률순위 + ROE순위)` 로 계산합니다.

- 대상: 해당 시장의 **`평가:true` 종목 전체**
- 이익수익률순위: `지표.PER > 0` 인 종목만 PER 오름차순으로 1,2,3…
- ROE순위: `지표.ROE != null` 인 종목만 ROE 내림차순으로 1,2,3…
- 순위가 없는 종목은 **평가 종목 총 개수 N** 을 순위로 사용

### 3.3 종목 선정 (`pick_stocks`)

1. `market.json.섹터순위` 에서 **점수 > 0 인 섹터**를 순서대로 뽑습니다. 하나도 없으면 전체 순위를 그대로 씁니다.
2. 각 뉴스 섹터에 대해 `섹터매핑[시장][뉴스섹터]` 후보를 앞에서부터 확인해
   **아직 쓰지 않았고 + 필터 통과 종목이 하나라도 있는** 첫 섹터를 고릅니다.
3. 고른 섹터에서 필터 통과 종목을 `rank_by` 로 정렬해 상위 **5종목**.
4. 이렇게 **최대 3블록**까지 만들고 멈춥니다.

## 4. 자동화

### 4.1 GitHub Actions (`.github/workflows/ristock-daily.yml`)

- cron 2회: `30 7 * * 1-5` (16:30 KST · 한국 마감 직후), `0 22 * * 1-5` (07:00 KST · 미국 마감 반영)
- `workflow_dispatch` 로 수동 실행 가능
- `permissions: contents: write`, `concurrency` 로 중복 실행 차단
- 시장별로 독립 실행 → 한쪽이 실패해도 다른 쪽은 배포
- cron은 **기본 브랜치에서만** 동작합니다 (main 병합 후부터 자동 실행)

> ⚠️ GitHub 서버 IP는 네이버 금융이 차단할 수 있습니다. 한국 재무·수급이 비면
> `manifest.실행.메모` 에 사유를 남기고 **기존 한국 데이터를 유지**합니다. PC 예약 실행이 이를 보완합니다.

### 4.1-1 앱에서 누르는 '브리핑 다시 받기' (2026-07-29)

폰에서 **지금 시각 기준으로** 브리핑을 새로 받는 길입니다.

```
앱 버튼 → 백엔드(Apps Script) → GitHub workflow_dispatch(mode=brief)
       → pipeline --only-brief (지수 + 10개국 뉴스, 18초~3분) → publish → 앱이 감지해 새로고침
```

- **왜 백엔드를 거치나**: 정적 페이지는 깃허브 실행을 부를 권한(토큰)을 가질 수 없습니다.
  토큰을 화면에 두면 누구나 남의 저장소 작업을 돌릴 수 있습니다.
  그래서 토큰은 Apps Script 의 **스크립트 속성**에만 두고, 앱은 백엔드에 부탁만 합니다
  (설치법: `docs/ristock_브리핑버튼_설치.md`).
- **종목은 다시 받지 않습니다.** `--only-brief` 는 `market.json` 과 `manifest` 만 새로 씁니다.
  600종목까지 받으면 10분이라 폰 앞에서 기다릴 수 없습니다.
- 이 모드는 '성공한 시장' 이 늘 비어 있으므로 **성패 판정을 따로 합니다**
  (브리핑을 새로 썼는가). 그러지 않으면 멀쩡한 실행이 실패로 끝나 실패 메일이 갑니다.
- 남용 방지: 백엔드가 **3분 쿨다운**을 겁니다(같은 회차가 겹쳐 도는 것을 막습니다).
- 토큰이 없거나 백엔드가 답하지 않으면 앱은 **최신 데이터만 다시 불러오고 그 사실을 알립니다.**
  아무 일도 안 하면서 '갱신했다'고 말하지 않습니다.

### 4.2 PC 예약 실행

- `tools/ristock_실행.bat` — 더블클릭 1회 실행
- `tools/ristock_스케줄등록.ps1` — 윈도우 작업 스케줄러에 매일 등록/해제
- 순서: `git pull --rebase` → 엔진 실행 → `ristock/data/` 만 커밋 → `git push`
- 충돌 방지: 생성 직전 `git checkout origin/<브랜치> -- ristock/data` 로 원격 상태를 받고 통째로 다시 씁니다
  (데이터는 매번 전량 재생성되므로 병합이 필요 없습니다)

## 5. 화면 (PWA)

Ri-weather와 같은 토스풍 라이트 테마를 씁니다(`css/style.css` 토큰 참고). 포인트 색만 파랑 계열.
한국 관행대로 **상승=빨강, 하락=파랑**.

| 화면 | 내용 |
|---|---|
| 오늘 브리핑 | **브리핑 시각 + 다시 받기** · **오늘의 지수** · 시장 분위기 한 줄 · 섹터 순위 Top5 · **어제 대비 신규 편입/이탈** · 데이터 신선도 |
| 전략 | 전략 8종 목록 → 선택 시 한국·미국 섹터별 5종목 카드 (지수 급락일에는 경고 배너) |
| 나만의 전략 | 필터 8개 토글 + 순위 기준 선택 → 즉시 재계산 (localStorage 저장) |
| 종목 | 시총 300 목록 · 검색 · 섹터 필터 · 점수 상세 · ☆ 관심종목 |
| 종목 상세 | **맨 위에 주가 그래프(연·월·주·일)** → 종합 점수 · 주요 지표 · 평가 근거 · 순이익 · 뉴스 |
| 내보내기 | 현재 화면 결과를 CSV(엑셀에서 바로 열림, UTF-8 BOM)로 저장 |

- 데이터가 **3일 이상 지났으면** 상단에 눈에 띄는 안내를 띄웁니다.
- 모든 화면 하단에 **"스크리닝 참고자료일 뿐 투자 권유가 아닙니다"** 고지를 고정 노출합니다.
  내려받는 CSV·엑셀과 `data/*.json` 에도 같은 문장을 넣습니다 — 파일은 앱을 떠나 혼자 돌아다닙니다.
- 버튼 검증은 `document.elementFromPoint` 로 실제 터치 지점을 확인합니다 (CLAUDE.md 3-1).
