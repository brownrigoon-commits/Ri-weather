# 문구 사전 규칙 (i18n) — 2026-07-31

한·일 다국어를 위해 화면 문구를 사전으로 옮긴다. **이 문서의 규칙을 어기면 조용히 깨진다.**
설계 배경은 [해외진출_설계.md](해외진출_설계.md) D2.

## 어떻게 쓰나

```js
tr("bk.title")                              // "부킹/조인"
tr("bk.desc", { course: "파주CC" })          // 사전: "{course} — 가는 날을 고르면 …"
```

- 함수 이름이 `t` 가 **아니라 `tr`** 인 이유: 이 저장소에 `const t = …` 지역변수가 27곳 있다.
  전역 `t()` 를 만들면 그 함수들 안에서 가려져(shadowing) 터진다.
- 사전 조각: `js/i18n/src/ko.<파일>.json` → `python tools/build_i18n.py` → `js/i18n/ko.js`(생성물).
  **`js/i18n/ko.js` 를 직접 고치지 말 것** — 다음 배포 때 통째로 덮인다.

## 🔴 절대 옮기면 안 되는 것 — '값'과 '라벨'은 다른 존재다

화면에 보인다고 다 문구가 아니다. 아래는 **값**이라 한국어 원문 그대로 둬야 한다.

| 무엇 | 어디서 값으로 쓰이나 | 옮기면 |
|---|---|---|
| 베타 의견 분류 `오류/불편/아이디어/칭찬` | 서버가 이 문자열로 검증(`Code.gs` FB_CATS) | **이용자 의견이 재시도 없이 사라짐** |
| 캐디 샷 라벨 `티샷/세컨샷/서드샷/그린` | AI 응답을 이 라벨 정규식으로 쪼갬 | 캐디 카드 파싱 실패 |
| 프로필·동의 값 `여성`·`60대 이상`·`1년 미만` | 문자열 동치 분기 + localStorage 저장 | 캐디 인격화 죽음 + **기존 이용자 기록 단절** |
| 클럽 브랜드 `타이틀리스트` 등 | 피팅 엔진 매칭 값 | 피팅 전멸 |
| 통계 지역명(시/도) | 백엔드 집계 키 | 통계 단절 |
| 골프몬 URL 값 `p.set("tab","조인")`, 인원 `1인` | 외부 사이트가 받는 값 | 조인 목록이 안 열림 |
| 구장명 정규화어 `컨트리클럽`·`골프클럽` | 이름 매칭 값 | 부킹 딥링크가 폴백으로 강등 |
| `data-*` 속성값, localStorage 에 저장되는 값 | 상태 복원 비교 | 기존 사용자 설정 증발 |

**판별법 한 줄:** *이 문자열이 화면 밖(서버·저장소·엔진·URL)으로 나가거나 `===` 로 비교되는가?*
그렇다면 값이다 — 옮기지 않는다.

**흔한 모양:** `{ v: "1인", t: "1명" }` — `v`(값)는 그대로, `t`(라벨)만 `tr()` 로.
`clubfit.js` 의 `chipList` 가 이미 이 구조다.

## 키 이름 규칙

`<영역>.<무엇>` — 영역은 파일 단위 접두사를 쓴다.

| 파일 | 접두사 | 예 |
|---|---|---|
| booking.js | `bk.` | `bk.card.pang.join` |
| stay.js | `stay.` | `stay.filter.hotel` |
| loading.js | `wait.` | `wait.food.1` |
| legal.js | `legal.` | `legal.tos.title` |
| stats.js | `stats.` | `stats.err.offline` |
| index.html | `ui.` | `ui.search.placeholder` |
| app.js | `app.` | `app.wx.summary` |
| clubfit.js | `cf.` | `cf.q.carry7` |
| spirit.js | `sp.` | `sp.tab.manner` |

## 문구 쓰는 법

- **변하는 값은 문구에 박지 말고 `{이름}` 자리로 넘긴다.** 일본어는 어순이 달라서,
  `"파주CC 주변 숙소"` 처럼 붙여 쓰면 일본어판에서 문장을 다시 쪼개야 한다.
  → `"{course} 주변 숙소"` + `tr("stay.title", { course: name })`
- **한국어 조사(을/를·이/가·으로)가 붙는 자리를 조심한다.** `${name}으로` 같은 문구는
  일본어에서 의미가 없다. 가능하면 조사가 필요 없는 형태로 다시 쓰거나, 문장째 키로 만든다.
- HTML 이 들어간 문구는 그대로 사전에 담아도 된다(`<br>`, `<b>`). 다만 **문구 안에 태그를
  넣을지, 코드에서 감쌀지 한쪽으로 통일**한다 — 번역자가 태그를 깨뜨릴 여지를 줄인다.
- 배열은 쉼표로 이어 한 문구로: `"bk.dow": "일,월,화,수,목,금,토"` → `tr("bk.dow").split(",")`.

## 지키는 장치 (배포 관문)

| 검사 | 무엇을 잡나 |
|---|---|
| `python tools/check_i18n.py` | 사전에 없는 키(화면에 키가 그대로 노출) · **옮기면 안 되는 값이 사라졌는지** |
| `node tools/i18n_snapshot.js` | 한국어 화면 10개의 글자·속성·타이틀이 **추출 전후 완전히 같은지** |
| `node tools/run_sweep.js` | 문법 오류 · 사전이 안 실렸는지 · 키가 화면에 새는지 |

`release_courses.py` 가 배포 때 위 검사를 자동으로 돌린다.

⚠️ **스냅샷 통과 = 전부 안전이 아니다.** 스냅샷은 그 화면에 **실제로 뜬 글자만** 본다.
조건부로만 나오는 문구(오류 분기, 특정 데이터가 있을 때만 뜨는 안내)는 못 잡는다.
그런 문구는 옮길 때 눈으로 한 번 더 확인할 것.

## 작업 순서 (파일당 1커밋)

작은 파일부터 — 사고가 나도 되돌리기 쉽고, 패턴이 굳는다.

`booking.js`(끝) → `stay.js` → `loading.js` → `stats.js` → `legal.js` →
`index.html` → `app.js`(화면 단위로) → `clubfit.js`(마지막, 가장 큼)

`spirit.js` 는 **다른 창에서 작업 중이라 이번 회차에서 제외**했다. 그쪽 작업이 끝나면 옮긴다.
