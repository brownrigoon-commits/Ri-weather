## 3. 맛집 — 핫페퍼 그루메 API

- **키**: 리크루트 웹서비스 등록, 무료 — **사장님(Phase 0, 8/1 추가됨)**. 키가 오기 전 개발 착수 금지.
- **호출**(구장 좌표 기준 — 이용자 위치 아님, 좌표 수집 금지 원칙과 무관):
  ```
  https://webservice.recruit.co.jp/hotpepper/gourmet/v1/
    ?key={KEY}&lat={course.lat}&lng={course.lon}&range=5&order=4&count=30&format=json
  ```
  (range=5 → 반경 3km. 부족하면 2단계: 3km → 시군 단위 키워드)
- ⚠️ **착수 시 실측 2건**: ① 브라우저 CORS/JSONP 가부 — 안 되면 **RIW_BACKEND_JP 프록시**(별도
  Apps Script, D7 예정안) 경유 ② 호출 상한(문서에 기재 없음 — 조사 §6).
- **의무**: 크레딧 표기(이미지 또는 텍스트 — 맛집 화면 하단 "Powered by ホットペッパーグルメ").
  점포 정보 재판매 금지·음식점에서 대가 수취 금지(제휴 수익은 허용).
- **매핑** (app.js 맛집 정규형 → 핫페퍼 응답): 이름=`name`, 분류=`genre.name`, 사진=`photo.pc.l`
  (카카오 사진 프록시 불필요 — 응답에 포함), 링크=`urls.pc`(새 탭), 거리=좌표로 계산(기존 로직).
- **내비**: 구글맵 URL `https://www.google.com/maps/dir/?api=1&destination={lat},{lon}`
  (kakaomap:// 스킴 4곳을 NavProvider 로 — D4. 배선은 §8 순서 준수).

## 4. 숙박 — 라쿠텐 트래블 API

- **키**: 라쿠텐 applicationId(GORA 와 공용)+affiliateId — **사장님(Phase 0)**.
- **호출**:
  ```
  https://app.rakuten.co.jp/services/api/Travel/SimpleHotelSearch/20170426
    ?applicationId={ID}&affiliateId={AFF}&latitude={lat}&longitude={lon}
    &searchRadius=3&datumType=1&format=json
  ```
- 🔴 **측지계 함정(GORA 좌표와 같은 계열)**: `datumType=1`(세계측지계) 명시 필수 —
  기본값이 일본측지계인 판이 있어, 빼면 수백 m 어긋난다. **착수 시 1회 실측**으로 확정.
- ⚠️ **레거시 API 예제 금지** — 2026-02-09 폐지됨(조사 §2). 현행 20170426 판만.
- JSONP: GORA 에서 callback 지원 실측됨 — 같은 플랫폼이라 트래블도 가능 추정, **착수 시 1회 확인**.
- **매핑** (stay.js 정규형 `{id,name,cat,kind,...}`): 이름=`hotelName`, 가격=`hotelMinCharge`
  (**¥ — stay.js:151 won() 을 fmtPrice(n,cur) 로**, D8), 사진=`hotelImageUrl`,
  평점=`reviewAverage`/`reviewCount`, 링크=`hotelInformationUrl`(affiliateId 넣으면 제휴 URL 반환).
- 링크 카드: 야놀자·여기어때 자리 → 라쿠텐트래블·자란(리크루트) 링크로 교체(JP 프로필에서만).

## 5. 마이스코어 — 이미 거의 됨, 정직하게 두 단계

- **수기 입력·통계·백업**: 구장 이름만 물고 있는 국가 무관 설계라 **JP 구장에서 이미 동작해야 정상**.
  할 일 = 실기 확인 3가지: ① JP 구장 스코어 저장·조회 ② 백업·복구(복원 데이터에 JP 구장이 있으면
  holeimgdb_jp 지연 로드 트리거 — D10) ③ 통계 화면.
- **사진 OCR**: 프롬프트가 한국어+한국 티 명칭 고정(app.js:3909-3917). 일본 스코어카드(카트 인쇄물·
  GDO 앱 캡처)는 **실물 샘플 확보 후 2차 작업**. 그전까지: JP 구장에서 OCR 실패 시
  "일본 스코어카드는 준비 중 — 수기 입력을 이용해 주세요" 안내(있는 척 금지).

## 6. 부킹 — 라쿠텐 GORA (딥링크 먼저, 빈자리 표시는 2차)

- **Phase 0 게이트**: GORA 상용조건·affiliateId 확인 전 **배포 금지**(R6). 개발은 딥링크 골격까지 가능.
- **1차 — 딥링크** (골팡·골프몬 카드와 같은 자리, JP 프로필로 교체):
  - `bookingids_jp.js` 신설: golfdb 구장명 → GORA `golfCourseId` 매핑.
    생성: GORA 골프장검색 API `keyword={구장명}` → 후보 중 **좌표 검산**(GORA 좌표는
    **일본측지계 → WGS84 변환 후** golfdb 와 ±1km 대조 — D4의 함정 그대로) → 동명 구장은 현(県)으로 구분.
  - 카드 링크: 골프장상세 API 응답의 `golfCourseDetailUrl`·`reserveCalUrl`
    (affiliateId 파라미터를 넣으면 **API 가 제휴 URL 을 만들어 준다** — 수익화가 약관 안).
  - 조인(1인): GORA **1人予約** 딥링크 — 골팡 조인 자리 대응.
- **2차 — 빈자리·최저가 표시** (한국판에 없는 차별화, ko×JP 의 핵심):
  플랜검색 API(빈자리 재고·요금·2B3B 추가금·취소료) JSONP 직접 호출(실측 확인됨).
  날짜 선택 UI(booking.js 의 14일 날씨 연동)에 날짜별 최저가 뱃지. 429 대비 — bkweek 캐시 패턴 재사용.
- 백엔드 프록시가 필요해지면 **RIW_BACKEND_JP**(별도 Apps Script) — KR Code.gs 무접촉(D7).
