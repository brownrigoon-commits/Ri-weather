## 1. 오늘 고친 것 — 홀 자료가 틀려 있었다 (v229 배포 완료)

집에서 넘긴 과제 ⑤ "한국 tip 22개 오배치"를 파고들었더니, 공략 문구만의 문제가 아니었다.

### 무엇이 잘못돼 있었나

| 사고 | 규모 | 사용자에게 어떻게 보였나 |
|---|---|---|
| 남의 홀 공략이 붙음 | **5개 구장 23홀** | 3번홀을 보는데 8번홀 설명이 떴다. **AI 캐디 프롬프트에도 사실로 들어갔다** |
| 파·거리·핸디캡이 어긋남 | 같은 구장들 전부 | 파5 홀이 파4로, 509m 홀이 345m로 |
| 홀맵이 백지 | 한림안성CC 9장 | 흰 종이만 나왔다 |
| 홀맵이 하얗게 탐 | 롯데스카이힐 성주CC 18장 | 형체만 겨우 보였다 |

원인은 둘이다.

* `tools/universal_build.py` 의 `parse_generic` — 홀 이미지 앞뒤 **±2200자**를 잘라 그 안의
  **가장 긴 한국어 문장**을 공략으로 삼는다. 창이 옆 홀까지 덮으면 옆 홀 문장이 더 길어서 그게 뽑힌다.
* `tools/crop_map_only.py` 의 `_finish` — 배경색을 흰색으로 끌어올리는 보정이 **어두운 배경에도** 걸렸다.
  성주CC 야디지맵은 화면 전체가 짙은 초록이라 배율이 6배가 됐고 그림이 탔다. **원본은 멀쩡했다.**
  한림안성은 다른 이유 — 그린 모양만 그린 투명 PNG(`hole_green_0n.png`)를 흰 배경에 합성해 넣었다.

### 어떻게 고쳤나

* `tools/reparse_holes.py` **신설** — 홈페이지 템플릿 3종을 알아보고 홀 덩어리 단위로 정확히 다시 뽑는다.
  창을 어림잡지 않으니 옆 홀이 섞일 수 없다. 저장된 원본(`coursedata/homepages_auto/*/pages*`)만 읽고
  **재수집은 하지 않는다**.

  | 프로필 | 구장 |
  |---|---|
  | `holetitle` | 광주CC · 한림안성CC |
  | `holecontent` | 골드그린GC · 일레븐CC |
  | `tabhole` | 써닝포인트CC |

  ```
  python tools/reparse_holes.py                 # 무엇이 바뀌는지만 본다
  python tools/reparse_holes.py --write --images
  python tools/build_holeimgdb.py               # 재조립
  ```

* `tools/crop_map_only.py` — 밝은 카드(세 채널 모두 200 이상)일 때만 흰색 정규화하도록 고쳤다.
  성주CC 18장은 원본에서 다시 잘랐다(편차 3~24 → 35~62).

* 덤으로 얻은 것: 티별 거리표를 읽어 **티 사다리**가 생겼다(한림안성 화이트/레드, 써닝포인트 5티,
  일레븐 4~5티, 골드그린 3티). 없던 핸디캡도 들어갔다.

### 다시는 새어 나가지 않게 — 새 관문

`tools/check_holequality.py` 를 만들고 `release_courses.py` 에 끼웠다. 두 가지를 본다.

* **남의 홀 공략** — 공략 본문의 홀 표기(`HOLE 3`·`3Hole`)나 파 표기(`Par 5`)가 그 홀과 다르면 실패
* **백지 홀맵** — 64×64 회색조 표준편차 < 18 이면서 평균 밝기 > 215 이면 실패(정상은 편차 70 언저리)

일부러 고장 내서 확인했다(관문을 믿으려면 이게 있어야 한다):

```
① 손대기 전            나감값 0  통과
② 남의 홀 공략 심음     나감값 1  ✖ 광주CC OUT 1번 — 공략 본문이 HOLE 7 입니다
③ 홀맵을 백지로 바꿈    나감값 1  ✖ 광주CC OUT 1번 — 백지에 가깝습니다(편차 0·밝기 252)
④ 되돌린 뒤            나감값 0  통과
```

배포 관문 통과 기록: `무결성 4221홀 · 티 거리 · 홀 자료 품질 0건 · 출처 · 브랜드명` 전부 OK →
`verify_deploy.py --wait` **v229 확인 완료**. 실서버에서 한림안성 1번홀 이미지가 661×900 실사 홀맵으로 나온다.

## 2. 막힌 지점 — 사장님이 **딱 한 번** 눌러 주셔야 합니다 (2분)

일본 구장 공식 홈페이지 895곳 찾기(집 문서 과제 ①)가 여기서 멈춰 있다.

### 무슨 일이 있었나

* 집에서 "검색 API 키가 필요하다"고 적어 두셨는데, 도구(`tools/jp/find_official_jp.py`)는 원래
  **키 없는 DuckDuckGo** 를 쓴다. 회사 망에서는 처음에 됐다 — 그래서 전체 검색을 걸었다.
* 그런데 십수 회 만에 **봇 감지**가 떴다(HTTP 202 + anomaly 페이지, 결과 0건).
  **차단은 우회하지 않는다**는 우리 원칙대로 접었다. 차단 중에 기록된 "못 찾음" 27건은
  가짜라서 지웠다(재개하면 다시 찾는다).
* 대신 **공식 유료 경로**를 붙였다 — Google Custom Search JSON API(하루 100회 무료, 이후 1,000회당 $5).
  `--engine cse` 를 추가했고 `.cse_key` 파일이 있으면 자동으로 쓴다.
* 사장님 GCP(TOURLIST 프로젝트)에서 **Custom Search API 사용 설정 + 키 발급(이 API 하나로 제한)**
  까지 제가 했고, 키는 `tools/jp/.cse_key` 에 저장했다(gitignore 대상).

### 사장님이 하실 일 — 검색엔진 ID(cx) 만들기

만들기 화면에 **reCAPTCHA("로봇이 아닙니다")** 가 있다. 봇 확인은 제가 통과하지 않는 것이 원칙이라
이 한 칸만 남겨 뒀다.

1. https://programmablesearchengine.google.com/controlpanel/create 접속(brown.rigoon 계정)
2. 이름 `tourlist-jp-official`, 사이트 칸은 **비워 둔다**(비우면 전 웹 검색)
3. **로봇이 아닙니다** 체크 → **만들기**
4. 만들어진 검색엔진의 **검색엔진 ID**(cx, `a1b2c3...` 모양)를 복사
5. 파일 `C:\Users\PC\Desktop\Ri-weather\tools\jp\.cse_key` 를 메모장으로 열어
   **둘째 줄**에 붙여넣고 저장 (첫 줄은 이미 API 키가 들어 있다 — 건드리지 말 것)

그 다음은 제가 이어서 합니다:

```
python tools/jp/find_official_jp.py --limit 20      # 표본 확인
python tools/jp/find_official_jp.py                 # 전체 (하루 100회 무료 소진되면 다음 날 이어감)
```

대상은 1,140곳이다(2,014곳 중 이미 아는 778곳 + **파크골프·연습장류 104곳 제외** — 코스공략 대상이
아니라 검색만 낭비한다). 하루 100회 무료로만 돌리면 12일, 유료로 한 번에 돌리면 약 $5.7.
**둘 중 무엇으로 할지는 사장님 판단이 필요하다.**
