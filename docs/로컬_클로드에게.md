## 2. 이번에 바뀐 것 — 클럽 피팅 전면 재설계

기존: 드라이버 8+5문항 → 내 백 허브 → 아이언/웨지/퍼터 각 4문항
지금: **첫 화면에서 클럽을 고르고, 클럽마다 20문항 안팎의 전문 피팅**

### 흐름

```
[1] 클럽 선택        드라이버 · 아이언 · 웨지 · 퍼터
[2] 나에 대해(공통)   성별·나이·구력·평균타수 + 키·손목바닥·장갑호수·체력·템포·몸상태·주플레이
                     ※ 최초 1회만. localStorage riweather.fitprofile 에 저장
                       두 번째 클럽부터는 확인 한 장으로 대체 (25문항 → 16문항)
[3] 선호 브랜드      헤드 / 샤프트 따로 (클럽별로 목록이 다름)
[4] 클럽별 전문 문항
[5] 결과
```

문항 수: **드라이버 24 · 아이언 26 · 웨지 19 · 퍼터 22**

### 드라이버 — 전문 로직으로 다시 씀

기존 로직이 개인 경험 기반이라 편차가 크다는 사장님 지적으로 재작성했습니다.

- **로프트 계산 신설** — 드라이버 거리에서 가장 큰 변수인데 기존에 아예 없었습니다.
  스피드(7번 캐리)로 기본값 → 런치·스핀·타점 신호로 보정 → 8.5~12° 로 제한
- **출발 방향 × 휘는 방향 9조합**(`FLIGHT9`) — 출발은 궤도, 휨은 페이스.
  둘을 나눠 받아야 같은 '슬라이스'라도 처방이 갈립니다
- 페이스 타점(상하·좌우), 티 높이, 캐리 편차 → 길이·어택앵글 처방
- 쓰는 공까지 물어서, 스핀 과다면 클럽보다 공을 먼저 봅니다

### 아이언 · 웨지 · 퍼터

- **아이언** — 볼자국·디봇으로 라이각 방향, 어드레스 취향으로 헤드 타입,
  긴 아이언 실사용 여부로 세트 구성(빼라는 조언)
- **웨지** — 잔디 상태·벙커 자신감까지 바운스에 반영
- **퍼터** — 그린 빠르기로 헤드 무게, 손 위치로 로프트, 눈 위치로 길이
- **그립** — 독립 문항 신설. 손 길이·장갑 호수 기반 사이즈 + 땀·관절·테이퍼 규칙

### 결과 설명 — 이게 이번 작업의 핵심

사장님 지시: *"이 클럽을 추천하는 이유를 정말 자세히, 유저가 '와! 이거 써야겠네' 하도록."*

결과 화면 순서를 이렇게 고정했습니다. **바꾸지 마세요.**

```
① 판정                    그대로 유지 / 교체 검토
② 진단 리포트             "골퍼님의 스윙, 이렇게 읽었습니다"
                          — 항목마다 그 숫자를 왜 그렇게 읽었는지 함께
③ 추천 카드               로프트 · 길이 · 샤프트 · 헤드 · 그립
④ 그래서 이 조합입니다     각 추천을 ②의 진단과 직접 연결해 문장으로
⑤ 바꾸면 이렇게 달라집니다  기대 효과 + 돈 안 드는 처방(티 높이·길이 줄이기)
⑥ 다만, 이건 꼭 짚어드립니다  한계·주의 ← 이게 있어야 나머지가 믿긴다
```

분량: 드라이버 약 3,300자 / 아이언 2,600자 / 퍼터 2,400자 / 웨지 2,000자.
`explainDriver()` `explainIron()` `explainWedge()` `explainPutt()` 가 `{read, rest}` 를 돌려주고,
`read` 는 카드 앞, `rest` 는 카드 뒤에 들어갑니다.

### 현행 / 단종 2단 추천 + 가격대

사장님 확정: **1차는 지금 살 수 있는 최신 모델, 2차는 단종 포함 최적안.**
한국은 중고 시장이 커서 2차가 실제로 값어치 있는 정보입니다.

- 데이터에 `st`(cur/old) · `pr`(1 순정·보급 / 2 중가 / 3 고가) 필드 추가
- `pickTiers()` 가 현행 1순위 + 단종 최적안을 함께 뽑습니다
- 예산 문항이 `pr` 로 후보를 거릅니다

> ⚠️ 처음엔 "단종이 현행보다 점수가 높을 때만" 내밀도록 했더니 **45조합 중 0번** 떴습니다.
> 값어치는 거기 있지 않습니다 — **성능이 비슷한데 값이 내려가는 것**이 중고를 보는 이유입니다.
> 그래서 현행 1순위의 **85% 이상**이면 내밀고, 더 높을 때만 "더 잘 맞는다"고 따로 말합니다.

## 6. 이번에 겪은 함정 — 같은 실수 반복 금지

### 🔴 서비스워커가 테스트를 속인다

브라우저 테스트에서 **이전 배포본이 캐시로 서빙돼 "고쳤는데 그대로"** 가 나왔습니다.
일부러 고장을 냈는데 검사가 통과하길래 코드를 의심했는데, 범인은 캐시였습니다.

```js
browser.newContext({ serviceWorkers: 'block' })   // 테스트에서는 반드시
```

### 🔴 검사는 반드시 자가검증하고 쓸 것

`clubfit_check.js` 에 **구멍이 3개** 있었고, 일부러 고장을 내서 찾았습니다:
① 화면이 안 넘어가도 통과 ② 결과 렌더 실패를 못 잡음 ③ 위의 서비스워커 캐시

4가지 고장(내부 용어 누출 / undefined 노출 / 문항 막힘 / 엔진 사망)을 넣어
**4/4 잡히는 것**까지 확인했습니다. 검사를 고치면 이 과정을 다시 하세요.

### 🔴 아이콘은 항상 원본에서만 만들 것

이미 처리된 `assets/*.png` 를 다시 돌려서 **크기·자르기가 누적되는 사고**가 있었습니다.
아이언 클럽 헤드가 잘린 채로 남았고, 로그로는 몰랐고 눈으로 보고 알았습니다.
→ 원본을 `assets/src/` 에 넣고, `build_club_icons.js` 는 거기서만 읽습니다.

### 🔴 SVG 요소에 `className` 대입 금지

`#cf-golfer` 는 SVG(foreignObject)라 `el.className = ...` 이 **throw** 합니다.
`setAttribute("class", ...)` 만 쓰세요.

### 🔴 마스크용 이미지는 알파가 단단해야 한다

`golfer.png` 는 픽셀의 **100%가 반투명**이라 혼자 회색으로 떠 보였습니다.
`build_club_icons.js` 가 알파를 단단하게 만듭니다. 새 이미지도 반드시 이 도구를 거치세요.

### 🟡 `.nojekyll` 이 0바이트인 건 정상

내용 없는 표식 파일입니다. 검증 스크립트에서 "빈 파일 = 실패" 로 잡으면 오탐입니다.

### 🟡 색 역할을 합치지 말 것

`--brand`(로고 그린) / `--primary`(흰 글씨 버튼용) / `--primary-ink`(흰 배경 위 글씨)
/ `--flag`(빨강, 핀·오버파) / `--rain`(파랑, 강수 데이터).
클럽 이름 구분색은 이 다섯과 겹치지 않는 색으로 골랐습니다 — **클럽 구분 전용**입니다.
