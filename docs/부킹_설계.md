## 1. 왜 두 단계로 가는가 — 남의 목록을 우리 화면에 옮기는 건 제휴 후에만

| 근거 | 내용 |
|---|---|
| **판례** | 예약 앱이 경쟁 앱의 숙소 목록을 크롤링해 쓰다가 **10억원 배상** 판결(서울중앙지법 2018가합508729, 성과도용). 부킹 사이트의 티타임 목록을 무단으로 가져다 보여주는 것이 정확히 이 사안입니다. 코드 주석에도 이미 기록돼 있습니다. |
| **차단 의사** | 골팡은 브라우저가 아닌 요청에 **2020년 날짜의 가짜 점검 페이지**를 줍니다(2026-07-28 실측). 수집을 명시적으로 거부하는 사이트입니다. |
| **신뢰 원칙** | 티타임·요금은 분 단위로 바뀝니다. 수집해 보여주는 순간 반드시 틀린 값을 보여주게 됩니다. **"틀릴 수 있으면 표시하지 않는다"** — 이 앱의 제1원칙. |

→ **1단계**: 데이터 복제 없이 "정확한 자리로 보내주기" (지금 바로 가능)
→ **2단계**: 제휴 API로 실시간 티타임을 우리 화면에 표시 (제휴 후)

숙박 메뉴와 같은 구조입니다. 숙박도 지금 이 방식으로 돌고 있습니다.

## 3. 1단계 화면 설계 — "부킹 허브"

진입: 구장 허브 6번째 타일. 타일 문구는 `부킹 / 티타임 · 조인 · 골팡 · 골프몬`.

### 구성 (위에서 아래로)

1. **날짜 고르기 = 우리 7일 예보 스트립** — 요일·하늘·기온·강수확률. 기본 선택은
   다가오는 토요일. 날짜를 고르면 아래 모든 링크의 날짜가 함께 바뀝니다.
   - 이게 우리만 줄 수 있는 결합가치입니다: **날씨를 보고 날짜를 정하고, 그 날짜
     티타임으로 바로 간다.** 골팡·골프몬에는 날씨가 없습니다.
   - 비 예보가 강한 날을 고르면 한 줄 안내: "일요일은 강수 70% — 토요일이 나아 보여요"
2. **연결 카드** (누르면 새 창)
   - 골팡 부킹 / 골팡 조인 — 구장 ID 있으면 `rd_date+clubname`, 없으면 `rd_date+sector`(지역 목록)
   - 골프몬 — 구장 ID 있으면 `/search/booking?startDate+golfFk+golfFkName`, 없으면 `/search/bookingsearch`(검색 화면)
   - 구장 공식 홈페이지 예약 — **이미 보유한** 홈페이지 URL(coursedata/homepages, 232곳)
3. **고지문**: "예약·결제·취소는 각 사이트에서 진행됩니다. 티타임과 요금은 실시간으로
   바뀌므로 각 사이트에서 확인하세요."

가격·잔여 티타임은 **표시하지 않습니다** (1절의 세 가지 이유). 화면 시안은 2026-07-30
대화에 첨부.

### 날짜 파라미터에 대해 — 숙박의 교훈과 다른 점

숙박에서는 날짜 파라미터를 붙였더니 숙소가 안 나와서 뗐습니다. 부킹은 다릅니다:
골팡·골프몬 목록 URL의 날짜 파라미터는 **그 사이트 홈 화면이 스스로 쓰는 공식 규격**임을
실측으로 확인했습니다. 붙여도 됩니다. 단, 구현 후 실기기에서 반드시 재확인.

## 4. 데이터·코드 설계

| 항목 | 내용 |
|---|---|
| 새 파일 | `js/booking.js` — `openBookingView(course)`. stay.js 패턴 그대로 |
| 지역 매핑 | 구장 주소 앞 토큰(경기/충북/전남…) → 골팡 `sector` 코드 표. 매핑 실패 시 sector 생략(전체 목록) — 틀린 지역으로 보내느니 전체가 낫다 |
| 구장 ID 표 | `coursedata/booking_ids.json` — `{ "구장명": { "golfpang": 81, "golfmon": 516 } }` |
| ID 등록 방식 | **수동.** 자동 수집은 하지 않습니다(골팡의 차단 의사 존중). 방문 구장·인기 구장부터 실제 브라우저로 확인해 채웁니다. 비어 있어도 폴백으로 동작하므로 빈 표로 출시 가능 |
| 구장명 정규화 | 숙박의 `stayQuery` 교훈 — "CC/컨트리클럽/GC/골프클럽" 표기 차이를 `bookingQuery()` 로 흡수 |
| 대기 화면 | WAIT 문구 2~3개: "가는 날 하늘부터 보고 있어요" 류 |
| 계측 | `STATS.hit("feature","booking_open")` + `booking_out_golfpang` 등 **아웃바운드 클릭별 집계** |

계측이 중요한 이유: **"우리가 골팡에 월 N건을 보내고 있다"는 숫자가 2단계 제휴 협상

## 7-1. 1차 사용 후 수정 (2026-07-30, 사장님 폰 확인)

| 골팡이 데스크톱 화면 | `www.golfpang.com/web/…` 로 보내고 있었음 | **`m.golfpang.com/m/round/booking_main.do`** 로 |

### ⚠️ 골팡 모바일의 한계 — 알고 쓰세요
모바일에서는 **구장까지 걸어줄 수 없습니다.**
구장 필터가 걸린 모바일 목록(`m/round/bookListTmp.do`)이 **POST 전용**이라
링크로는 도달이 안 됩니다(GET 으로 열면 로그인 화면으로 튕김 — 세션이 있어도 동일, 실측).

전달되는 것: **날짜 + 지역**. 구장은 목록에서 한 번 고르게 하고,
카드 부제에 `08/01 · 파주 선택하세요` 처럼 **무엇을 고르면 되는지** 적어 둡니다.

데스크톱(`www`)은 구장까지 걸리지만 폰에서 글씨가 읽히지 않습니다.
사장님 지시(2026-07-30)대로 **모바일 우선**이 맞다고 판단했습니다.
골팡이 모바일에도 GET 딥링크를 열어주면 그때 되살리면 됩니다.

### 골프몬 조인
`&tab=조인` 을 붙이면 조인 목록으로 열립니다(실측).

## 7-1-2. 2차 수정 (2026-07-30) — 로고 · 조인 인원

### 각 서비스 로고를 카드에 넣음
`assets/brand/golfpang.png` · `assets/brand/golfmon.png`
(각 사이트가 자기 화면에 쓰는 로고. "그 서비스로 간다"는 표시로 쓰는 것 = 지명적 사용.
 핫링크하지 않고 내려받아 저장소에 둡니다 — 남의 서버에 부담을 주지 않기 위해서.)

- 골팡 로고는 가로로 긴 워드마크(259×51)라 정사각 칸에선 아주 작아진다 → **로고 칸만 52px**로.
- ⚠️ 로고 칸이 들어오면서 가로가 좁아져 긴 제목이 "…" 로 잘렸다.
  **제목은 짧게**("골팡 부킹"·"골프몬 조인"), 날짜·조건은 부제로 내렸다.
  sweep 이 `scrollWidth > clientWidth` 로 잘림을 검사한다.

### 조인 인원 고르기
`BK_JOIN_COUNTS` = 전체 · 1인 · 2인 · 3인 · 부부커플 → 골프몬 `filterJoinCount` (실측).

⚠️ **골팡에는 인원 필터가 없다.** 조인을 유형(초대·부부·남성·여성 = `jitype`)으로 나눈다.
모바일 폼에 `noma` 칸이 있지만 **화면 어디서도 호출되지 않아 값의 뜻을 확인할 수 없었다.**
뜻을 모르는 파라미터를 찍어 보내면 엉뚱하게 걸러진 목록을 보여주게 된다 → **보내지 않는다.**
화면에도 "인원 조건은 골프몬에만 걸립니다"라고 밝혀 둔다.
sweep 이 골팡 링크에 `noma=|jitype=|filterJoinCount=` 가 붙으면 잡는다.

### ⚠️ 골팡이 외부 딥링크를 막고 있다 — 확정 (2026-07-30 실측)
"눌러서 들어가면 파주가 나오는데 왜 링크로는 안 되나"에 대한 답:

| 시도 | 결과 |
|---|---|
| `m/round/bookListTmp.do` **GET** (전체 파라미터) | 로그인 화면으로 튕김 |
| 우리 앱에서 그들과 **똑같은 POST** | **2020년 날짜의 가짜 "서비스 점검 중" 페이지** |
| `m/round/booking_list.do` | 200 이지만 목록 없는 껍데기 |

마지막 줄이 결정적이다. 외부에서 오는 요청을 **의도적으로 막고 있다.**
사이트 안에서 누르는 건 되고 밖에서 링크로 건너뛰는 건 안 되는 것 —
기술적 한계가 아니라 골팡의 정책이다. 우회하지 않는다.
우리가 보낼 수 있는 건 **날짜 + 지역**까지이고, 카드에
`08/01 · 강북/경춘 칸 → 파주` 처럼 **누를 곳을 적어준다.**

## 7-2. 구현 기록 — 다음 사람이 알아야 할 것 (2026-07-30)

### 구장 번호는 어떻게 채웠나
두 사이트 **자기 화면의 공개 선택 UI** 에서 이름↔번호를 읽었습니다.
티타임 목록(그들의 상품)이 아니라, 그들 사이트로 정확히 보내주기 위한 식별자입니다.

- 골팡: 부킹 목록 화면의 `골프장` 드롭다운(지역을 고르면 채워짐) — 542곳
- 골프몬: 검색 화면이 스스로 부르는 `golf_name_list`(검색 자동완성 재료) — 551곳

`tools/build_booking_ids.py` 가 우리 232곳과 이름을 맞춥니다(업종어·괄호 제거 후 비교).

**틀린 매칭을 막는 장치 3겹** — 엉뚱한 구장 티타임을 띄우면 그게 곧 거짓 정보입니다.
1. **동명이인은 버린다** — 같은 핵심이름이 둘 이상이면 아예 등록하지 않음(21건)
2. **좌표로 검산** — 골팡 지역코드가 덮는 범위 밖이면 버림.
   실제로 `그린필드 CC`(경기 37.38)가 골팡 `그린필드(구.제피로스)`(제주)에 붙는 걸 잡아냈습니다.
3. **골프몬 번호는 골팡+좌표까지 통과한 구장에만** 붙임 — 골프몬은 좌표를 안 주므로 혼자서는 검산 불가

⚠️ 좌표 상자를 좁게 잡으면 정상 매칭까지 죽습니다(여주 lon 127.7, 태안 lon 126.1).
   **큰 오류만 걸러내는 용도**로 넉넉하게 잡으세요.

### 겪은 사고 — 새 화면을 만들 때 반드시
**`js/app.js` 의 `VIEWS` 등록부에 넣어야 합니다.** 안 넣으면 `showOnly()` 가
다른 화면만 끄고 새 화면은 켜주지 않아 **메뉴를 눌러도 하얀 화면**만 뜹니다.
DOM 에는 내용이 다 들어 있어서 '내용이 있는지' 보는 검사로는 안 잡힙니다.
→ sweep 3-7 이 **보이는지(hidden)** 를 봅니다. 일부러 빼서 잡히는 것까지 확인했습니다.

### 검사 (tools/sweep.js)
- **3-7** 허브 메뉴 ↔ 화면 ↔ VIEWS 등록 대조
- **3-8** 링크 정확성 — 날짜 파라미터, 번호 있을 때/없을 때 폴백, 번호표 값 검산
- **3-9** 부킹 화면을 실제로 열어 보이는지·비었는지·**요금이 표시되지 않는지**

마지막 항목이 중요합니다. 제휴 전에는 요금을 우리 화면에 쓰면 안 되므로,
`\d{1,3},\d{3}원` 패턴이 화면에 있으면 배포를 멈춥니다.
